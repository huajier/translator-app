## 一、怎么填

### 填法

在最后一列「你的选择」里写字母。比如阶段 0 选 A、A、B，就在对应行写 `A`：

| 编号  | 要决定什么       | ... | AI 推荐 | 你的选择  |
| --- | ----------- | --- | ----- | ----- |
| 0-1 | 用哪个工具写代码    | ... | A     | **A** |
| 0-2 | 用哪个版本的 .NET | ... | A     | **A** |
| 0-3 | 代码怎么备份      | ... | B     | **B** |

### 三条规则

1. **⭐ 标记的是 AI 推荐项**。推荐理由写在每个编号下面的「为什么推荐」行。
2. **不确定就选推荐项**，或者干脆说「都按推荐来」。
3. **留空 = AI 必须停下来问你**，不许自己猜。

### 两种特殊填法（重要）

大部分决策点填**一个字母**就行。但有 8 个决策点，AI 的推荐是「两个一起做」或者「一个为主、另一个兜底」——它们**不是二选一**，表格里带了特殊标记：

| 标记  | 含义                            | 怎么填                    | 是哪几个编号           |
| --- | ----------------------------- | ---------------------- | ---------------- |
| 🔗  | **组合型**：两个都要做，不是二选一           | 填 `A+B`                | 4-2、6-1、9-4、12-1 |
| 🧩  | **分层型**：一个当主力，另一个当自动兜底 / 以后扩展 | 填 `B>A`（主>辅），或直接写「按推荐」 | 7-1、7-2、8-2、10-1 |

> 举例：`4-2` 填 `A+B` 意思是「谷歌和必应两个免费通道都做，一个不通试下一个」，不是让你在两者里挑一个。

### 最省事的填法

如果你想快点开始，直接回一句：

```
都按推荐来
```

AI 就会用全部 ⭐ 项（8 个组合/分层项也照推荐执行）。**唯一要注意的是 9-2**（打包体积优化）——如果你在 1-1 选了 WPF 界面，9-2 就不能选 B，原因写在那一条的备注里。

> **为什么推荐 1-3 选 B**：A 太简陋，没验证到关键点（托盘）；C 把阶段 2 的活提前干了，会打乱节奏。

### 阶段 2 · 组合键 + 拖拽监听

| 编号  | 要决定什么          | 选项 A              | 选项 B                | 选项 C                    | AI 推荐  | 你的选择 |
| --- | -------------- | ----------------- | ------------------- | ----------------------- | ------ | ---- |
| 2-1 | 🔴 怎么监听全局按键和鼠标 | 手写低级钩子（Win32 API） | 用现成开源库（SharpHook 等） | 定时轮询按键状态                | ⭐**A** | A    |
| 2-2 | 触发方式           | 固定 Ctrl+Alt+左键拖拽  | 可配置组合键              | 双模式（组合键 + 双击 Ctrl 翻剪贴板） | ⭐**C** | C    |
| 2-3 | 框选时画面反馈        | 无反馈               | 半透明遮罩 + 亮色选框        | 十字光标 + 尺寸提示             | ⭐**B** | B    |

**为什么推荐 2-1 选 A**：这是整个软件的心脏。手写虽然代码量最大（约 200-300 行），但完全可控、不依赖第三方、出问题自己能查、体积最小。**而且写一次以后再也不用碰。** B 省一半代码但多一个依赖，库停止维护就要自己接手。C（轮询）最省代码，但一直吃 CPU、快甩鼠标会漏事件，还可能被游戏反作弊误判。
**为什么推荐 2-2 选 C**：多出来的「双击 Ctrl 翻剪贴板」非常实用——有些软件（扫描件、视频、游戏）根本框选不了文字，这时候复制一下再双击 Ctrl 就能翻。实现成本不高，但实用性提升明显。
**为什么推荐 2-3 选 B**：用户框选时最怕「我框对了吗」。全屏变暗、框内保持原色的做法，和主流截图工具一致，一眼就知道框住了哪里。

### 阶段 3 · 取词

| 编号  | 要决定什么         | 选项 A           | 选项 B            | 选项 C             | AI 推荐  | 你的选择 |
| --- | ------------- | -------------- | --------------- | ---------------- | ------ | ---- |
| 3-1 | 🔴 怎么拿到框里的文字  | 纯 OCR（截图识别）    | 纯剪贴板（模拟 Ctrl+C） | 混合：剪贴板优先，失败转 OCR | ⭐**C** | C    |
| 3-2 | 🔴 用哪个 OCR 引擎 | Windows 自带 OCR | Tesseract       | 云端 OCR（百度/腾讯等）   | ⭐**A** | A    |
| 3-3 | 识别前要不要处理图片    | 不处理            | 放大 2 倍 + 灰度化    | 二值化 + 按行切分       | ⭐**B** | B    |

**为什么推荐 3-1 选 C**：A 通用性最强（网页/PDF/视频/游戏全都能识别）但有错误率、要花时间；B 准确率 100%、几毫秒出结果，但只对「能选中文字」的软件有效，而且会覆盖你剪贴板里原来的东西。C 把两者优点都占了——这是有道、欧路这些成熟划词软件的标准做法。多花的功夫换来「什么场景都能用」。
**为什么推荐 3-2 选 A**：免费、离线、速度快（几十毫秒）、系统自带不用下载模型、不用申请任何账号。**唯一的小麻烦**：第一次用之前要在系统设置里装一下「光学字符识别」语言包，AI 会给你图文步骤。B（Tesseract）中文识别率明显不如现代引擎；C（云端 OCR）识别率最高但要联网、要申请账号、有额度限制，而且**你的屏幕内容要传到别人服务器上**。
**为什么推荐 3-3 选 B**：小字（小于 12 像素）识别率会大幅提升，代码不复杂，只多花约 50 毫秒。C 的「按行切分」能力在阶段 7（覆盖原文）会很有价值，那时候可以再回来升级。

> 🔗 **和阶段 7（决策 7-2）的依赖关系，提前说清**：7-2 推荐「按原文行数分行」，这需要 OCR 能给出每一行的坐标。**选 B 完全不影响**——Windows 自带 OCR 本来就返回每一行的坐标，阶段 7 会再把取词模块升级一次把行坐标用起来。3-3 的 C 只是把「按行切分图像」这件事提前做了而已。**所以这两项不冲突，你可以放心选 B。**

### 阶段 4 · 翻译内核

| ------ | ----------- | ------------ | ------------------- | ------------------------- | ----------- | ---- |
| 4-1    | 🔴 主翻译引擎用哪家 | DeepSeek API | 微软 Azure Translator | 百度翻译开放平台                  | ⭐**A**      | A    |
| 4-2 🔗 | 免费的兜底通道用哪个  | 谷歌翻译免费端点     | 必应/微软免费端点           | MyMemory / LibreTranslate | ⭐**A+B 都做** | A+B  |
| 4-3    | 什么时候切换引擎    | 手动切换         | 报错自动降级              | 自动降级 + 定期回探               | ⭐**C**      | C    |

**为什么推荐 4-1 选 A**：中文理解最好，翻译自然不像机翻；按量付费、单价极低（百万字约几块钱），日常用一个月花不了几块钱；接口和 OpenAI 兼容，代码好写。B 要注册 Azure 账号（要信用卡），国内访问偶尔不稳。C 注册最简单（手机号即可）但免费额度只有每月 5 万字，超出后比 DeepSeek 贵，翻译偏直译。
**为什么推荐 4-2 选 A+B 都做**：反正都要写兜底逻辑，多写一个成本不高。顺序建议 **谷歌 → 必应 → MyMemory**，一个不通试下一个。

> ⚠️ **必须知道的风险**：谷歌和必应的免费端点都是**非官方接口**（借用网页翻译的接口），随时可能失效。AI 不能保证永久可用。MyMemory 有正式文档、不会突然消失，但质量明显差一些、速度慢、公共实例经常限流。
> **为什么推荐 4-3 选 C**：A（手动）额度用完你得自己发现、自己去改设置，很烦。B（自动降级）省心，但免费通道质量差一些，你可能过了很久才发现「怎么翻得变差了」。C 在 B 基础上每 30 分钟偷偷试一次主引擎，恢复了就自动切回来，还在托盘弹个气泡告诉你——「自动切回来了还告诉你一声」这个细节，是成熟软件和新手软件的分水岭。

| ------ | -------- | ------------ | ------------ | ----------- | -------------- | ---- |
| 7-1 🧩 | 怎么「盖住」原文 | 统一半透明色块 + 译文 | 取样背景色填充 + 译文 | 不遮盖，只描边显示译文 | ⭐**B 为主，A 兜底** |      |

**为什么推荐 7-1 选 B 为主 A 兜底**：B（取样背景色）效果最惊艳，像原生替换；但遇到渐变背景、图片背景会穿帮。所以先试 B，检测到背景复杂（颜色方差太大）就自动降级成 A。C 作为设置里的快捷选项，留给「想对照看原文」的场景。

### 阶段 8 · 设置中心

| 编号     | 要决定什么           | 选项 A     | 选项 B         | 选项 C              | AI 推荐         | 你的选择 |
| ------ | --------------- | -------- | ------------ | ----------------- | ------------- | ---- |
| 8-1    | 设置界面怎么做         | 独立设置窗口   | 托盘右键菜单内嵌     | 本地网页设置页（WebView2） | ⭐**A**        |      |

| 8-3    | 🔴 API Key 怎么保存 | 明文存 JSON | DPAPI 加密后存文件 | Windows 凭据管理器     | ⭐**B**        |      |

**为什么推荐 8-1 选 A**：标准、稳、好维护。C 的「漂亮」不值得多背 100 MB 的 WebView2 运行时。
**为什么推荐 8-2 选 B + 便携模式**：默认用 `%APPDATA%`（Windows 标准做法，一定有写权限）；如果 exe 同目录存在 `portable.txt` 文件，就改用 exe 同目录——这样「绿色软件」和「标准安装」两种需求都满足。
**为什么推荐 8-3 选 B**：**你填的 API Key 等于你的钱包**。明文存 JSON 的话，任何能读到你电脑文件的软件都能看到你的 Key，拿去花你的钱。DPAPI 是 Windows 自带的加密接口，**只有你这台电脑的这个用户**能解开，拷到别的电脑上是乱码。代码只多 20 行，性价比最高。

| 9-3    | 开机自动启动    | 注册表 Run 键             | 启动文件夹快捷方式        | 任务计划程序          | —    | ⭐**A**     |      |
| 9-4 🔗 | 杀毒软件误报怎么办 | 买代码签名证书               | 提交误报申诉           | 换打包方式 + 白名单说明   | —    | ⭐**B + C** |      |

**为什么推荐 9-1 选 A**：你的硬性要求是「一键运行」。B 体积最小但对方必须先装 .NET 运行时，否则报错打不开。C 最专业但用户要「安装」而不是「双击」，还要学 Inno Setup 脚本。**A 是唯一真正满足「双击就能用」的。**首次启动要多 1-3 秒（要把自己解压到临时目录），可以接受。
**为什么推荐 9-2 选 C**：

> ⚠️ **这一项有坑**：**B（裁剪 Trim）和 WPF 不兼容！** 如果你在 1-1 选了 WPF（推荐项），9-2 选 B 会直接编译失败或功能异常。到时候别慌，改回 A 或 C 就行。
> C（ReadyToRun + 压缩）能减到约 60-80 MB，而且启动更快，是目前性价比最好的组合。
> **为什么推荐 9-3 选 A**：标准做法，而且任务管理器的「启动」标签里能看到、用户能自己关。**默认必须是关闭的**，让用户自己开——不要默认就开机自启，那叫流氓软件。
> **为什么推荐 9-4 选 B + C**：自己用的话足够了。买代码签名证书要 ¥1000-4000/年，个人开发者买 OV 证书还要企业资质。**除非你要发给很多人用，否则不用买。**

### 阶段 10 · 升级通道

| 编号      | 要决定什么        | 选项 A             | 选项 B      | 选项 C           | AI 推荐          | 你的选择 |
| ------- | ------------ | ---------------- | --------- | -------------- | -------------- | ---- |
| 10-1 🧩 | 新功能怎么加进来     | 配置开关（功能都编译在主程序里） | 插件 DLL 机制 | 内置脚本引擎         | ⭐**A 起步，B 预留** |      |
| 10-2    | 软件怎么更新       | 手动下载覆盖           | 内置自动更新    | 增量更新           | ⭐**A**         |      |
| 10-3    | 🔴 接口预留到什么程度 | 只留翻译引擎接口         | 翻译 + 取词接口 | 三层全留（翻译+取词+显示） | ⭐**C**         |      |

**为什么推荐 10-1 选 A 起步 B 预留**：现在把所有东西做成「配置开关」，但**接口设计成插件友好的样子**。等真的需要第三方插件时再加 B——因为接口已经在了，加 B 只需要写个「加载器」，不用改业务代码。
**为什么推荐 10-2 选 A**：个人软件，A 完全够用，而且最不容易出事。**「自动更新把自己更新坏了」是真实存在的坑**，不值得为省两步操作去冒这个险。
**为什么推荐 10-3 选 C**：这三个接口在阶段 3/4/5 本来就会自然形成，把它们**正式定义成接口**只是多写几行注释的事，但扩展性差别巨大。以后加「朗读」「双语对照」「翻译整页 PDF」都只需要加文件，不用改老代码。

### 阶段 11 · 本地离线翻译兜底（可跳过）

> ℹ️ **这一阶段是可选的**。如果你基本不断网、或者不在意断网时翻不了，可以直接跳到阶段 12。

| 编号   | 要决定什么     | 选项 A            | 选项 B                  | 选项 C                 | AI 推荐  | 你的选择 |
| ---- | --------- | --------------- | --------------------- | -------------------- | ------ | ---- |
| 11-1 | 用哪个本地翻译引擎 | Argos Translate | CTranslate2 + OPUS-MT | ONNX Runtime + 量化小模型 | ⭐**C** |      |
| 11-2 | 怎么集成进主程序  | 打包进主程序          | 独立子进程                 | 可选下载组件               | ⭐**C** |      |

**为什么推荐 11-1 选 C**：A（Argos）要拖一个 Python 运行时进来，多 100 MB 很别扭。B（CTranslate2）质量最好但模型转换要折腾。C（ONNX Runtime）虽然有分词器要自己实现（这块最容易出错），但它是**唯一能和 C# 主程序干净融合**的方案，不会引入 Python 这个庞然大物。
**为什么推荐 11-2 选 C**：你的硬性要求是「一键运行的 exe」，那主 exe 就保持轻量，离线包按需下载。**而且要默认不下载**，在设置里给一个明显的按钮。
**为什么推荐 11-3 选 B**：让用户自己选，明确知道「我下载了什么、占了多少空间」。A 只能中英互译；C 第一次翻译要等下载几分钟，体验差。

### Q4 补充：怎么申请 DeepSeek API Key（5 分钟）

1. 浏览器打开 `platform.deepseek.com`
2. 手机号或邮箱注册、登录

5. 到「充值」页面充 ¥10 试试（够用很久了）

> ⚠️ **安全提醒**：这串 Key 等于你的钱包。**不要发到聊天群、不要截图发出去、不要传到 GitHub。** 如果怀疑泄露了，立刻去网站删除、重新创建一个。
