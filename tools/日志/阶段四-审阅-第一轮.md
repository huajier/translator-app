## 1. P0（必修，不做完不许进 T2）

### P0-1　端到端指标测不到，回放路径不经过翻译
- 方案把翻译插在 `src\TranslatorApp\App.xaml.cs:641`（拿 result）与 `:656`（`card.UpdateWith`）之间。
- 但回放走的是 `src\Core\Capture\ReplayRunner.cs:99` → `CaptureDispatcher.Shared.CaptureAsync`，**两条路不交叉**。
- 后果：§7「回放 80 张测端到端 P95 ≤800ms」是纸面数字，量不到翻译那一段。
- 改法：在 `ReplayRunner.RunAsync` 的 `:99` 之后、结果归档之前接一次 `TranslationService`（约 10 行），以 `translateEnabled` 为开关。回放此后是「识别 + 翻译」的同一条真机路径。

### P0-2　首次提示无持久化，会每次启动都弹
- `DebugToastWindow.ShowNotice`（`src\UI\Shared\DebugToastWindow.xaml.cs:346`）只活 3 秒，无「已弹过」标记 → 违反用户选的 b（首次弹一次）。
- 改法：settings.json 增第 6 键 `translateNoticeShown`（bool，默认 false），弹完写 true。
- 必须进 `src\Core\Capture\AppSettings.cs:266` 的 `Save()`。方案 §2 自己写过「漏写 Save 会被下次保存抹掉」，同一坑。

### P0-3　错误码映射自相矛盾，且 432 不存在
- §2 写「401/403 → 密钥无效 / 额度用尽」，§4 写「403 / 432 额度用尽」——两处打架；Azure Translator v3 **没有 432**。
- 按 D8：开工前抓一次官方错误码页，URL 抄进 `AzureTranslatorProvider` 类注释。
- 403 必须读响应体 `error.code` 再定文案（额度用尽 ≠ 凭据无权），不许拿 HTTP 状态码直接当结论。
- 401 = 密钥无效；408 = 超时；429 = 限流（冷却 + 「请求太快，稍等」，不许说成额度用尽）。删除 432。

### P0-4　失败文案缺用户点名的一句
- 用户原话：断网 / 额度用尽时要「原文别丢 + 一行原因 + **请重新框选**」。
- §4 五条文案只到「只显示原文」。四类失败（无网络 / 超时 / 额度 / 密钥）全部补「请重新框选」。
- 原则（方案已写对，保持）：认字成功必显原文，翻译失败只追加详情行，绝不覆盖、绝不白屏。
