## 4. P1：我自己造成的量具损坏，这轮只补了一半

上一轮我合 `feat-corpus-variants`（`9775bc3`）时用 `git checkout <分支> -- <文件>` 整文件覆盖，
把 `比对回放.ps1` 从 **544 行砍到 271 行**，丢了四样东西。执行 AI 这轮补回了 `-按行`（三个函数 +
`$actualRaw`），**还剩两样**：

### P1-L1 `-自检` 参数整段消失

原版 `param()` 里有 `[switch]$自检`，配 `Invoke-LineSelfCheck`（注入「改 1 字 / 删 1 行 / 加 1 行」，
必须各报 1 错，恢复后 0 错 —— S0 的闸门：自检不过 = 尺子坏，停，不许改识别代码）。

现在：参数没了，函数没了。实测（我亲手跑）：

```

→ 应测 56 段，判对 0 段，判错 0 段，缺 56 段
```

**PowerShell 对未知参数不报错**，于是它拿 `-自检` 当没看见，转头走段级比对，
把「没给对文件」报成「缺测 56 段」，然后**正常退出**。谁要是想验尺子，只会看到一堆「缺测」。

### P1-L2 `-Approve` 的退步闸门整段消失

原版 `-Approve` 有一道闸：写新基线前先比旧基线，**有退步就 `exit 1` 拒绝写**，
逃生门是 `-Force`（明知会掉几段也接受时用）。注释原文：

> 这一关不许靠人记得查 —— 让工具自己拒绝。
> 这轮要是跑得比上次差，按下去就等于把退步洗白成「本来就这样」，从此再也不报警。

现在：`$Force` 参数没了，`$wouldRegress` 比较没了。**`-Approve` 现在会老老实实把退步写成标准。**

（`grep -c 'Force'` 现在只剩 1 处，是 `New-Item -Force`，无关。）

### 为什么现在必须补

- 这轮之所以能「重量」，靠的就是 `-按行`。下一轮要是再动 `比对回放.ps1`，

- `-Approve` 是整套流程里**唯一会写标准**的操作，没有闸门等于「基线可以随便刷」。

## 6. 教训（写给下一个接手的 AI）

1. **`git checkout <分支> -- <文件>` 是整文件覆盖，不是合并**。我用它合 `feat-corpus-variants`
   的两个脚本，把一个 544 行的量具砍成 271 行，丢了 `-按行` / `-自检` / `-Force` 退步闸门 /
   四个函数，而**当时一路绿灯**——因为 PowerShell 对未知参数静默忽略、exit code 还是 0。
   以后跨分支合脚本，合完必须 `diff` 一遍原文件，确认没丢东西。
2. **量具会烂，而且烂得毫无声音**。这轮能发现，仅仅因为「要验模型」这件事逼着人去看 L_行
   有没有打印出来。以后动 `比对回放.ps1`，跑完先确认 `L_行` 那几行真的出现了。
3. **改日志格式等于改所有解析它的脚本**。第 11 轮把回放日志改成
   `认字 NNN ms / 翻译 NNN ms / 合计 NNN ms` 之后，`回放-行.ps1:69` 的
   `耗时\s+(\d+)\s*ms` 就再也没匹配上，耗时一列静默空了十几轮。
4. **还原日志里的整块原文必须把 ` / ` 换成 `⏎`**，否则 L_整块 从 73.1% 掉到 1.9%——
   判分脚本按 `⏎` 拆行，不知道 ` / ` 是什么。
