用途：用户说「要留好模块化接入的地方，方便我随时增加新东西（我记得之前搞过）」。
**先说实话：之前搞过的那个东西没有接线。** `src\Core\Modules\` 里只有一个 125 字节的 README，
`grep -rn "Modules" src/ --include=*.cs` **零命中**——目录建了，代码从来没引用过它。
所以「模块化」这件事的真实状态是：**有 2 个天然长出来的接缝，没有模块系统。**

本文件不新建任何架构，只把**现有的 2 个接缝标清楚**，外加一张「你想加的东西该插哪」的对照表。

## 1　现在真正存在的接缝（只有 2 个）

全仓 `grep "abstract class" src/ --include=*.cs` → **0 条**。只有 2 个 interface：

### 接缝 A：取词通道 `ITextCapture`

`src\Core\Abstractions\ITextCapture.cs:15`

```csharp
internal interface ITextCapture
{
    string ChannelName { get; }                    // "Clipboard" / "WindowsOcr" / "RapidOCR"
    bool IsAvailable { get; }                       // 语言包没装就说 false
    Task<CaptureResult> CaptureAsync(CaptureRequest request, CancellationToken cancellationToken);
}
```

两个实现：`ClipboardTextCapture`、`OcrTextCapture`（`partial class`，拆成 7 个文件共 5493 行）。

**接缝在哪断开**：`src\Core\Capture\CaptureDispatcher.cs`
- `:31` `private readonly ClipboardTextCapture _clipboard = new();`
- `:32` `private readonly OcrTextCapture _ocr = new();`
- `:54` `private static readonly bool UseClipboardChannel = false;`（不用 `const`，否则编译器把剪贴板那段判成死代码报 CS0162）
- `:116` `CaptureResult ocrResult = await OcrWorker.RecognizeAsync(_ocr, request, cancellationToken)`

**注意**：这里的字段类型写的是具体类，不是 `ITextCapture`。因为调度器要调 `OcrTextCapture` 的额外成员（降级标记、实验开关），不是纯接口调用。**要插第三个通道，改的是这两行字段 + 一个 if 分支，不是改接口。**

### 接缝 B：翻译提供方 `ITranslationProvider`

`src\Core\Translate\ITranslationProvider.cs:17`

```csharp
internal interface ITranslationProvider
{
    string Name { get; }
    Task<TranslationResult> TranslateAsync(string text, string to, CancellationToken ct);
}
```

一个实现：`BingFreeProvider`。接口注释里写死了留它的理由：**免密钥通道没有公开文档，随时可能改协议或关掉，换一家就是新写一个类。**

**接缝在哪断开**：`src\Core\Translate\TranslationService.cs`
- `:296` `private ITranslationProvider GetProvider()`
- `:298` `string endpoint = AppSettings.TranslateEndpoint;`
- `:301` `if (_provider is not null && _providerEndpoint == endpoint) return _provider;`
- `:302` `_provider = new BingFreeProvider(endpoint);`
- `:303` `_providerEndpoint = endpoint;` → 换 endpoint 自动重建 + `_cache.Clear()` + 打日志

**这是全仓最干净的注入点**：想换翻译源，只改 `:302` 一行。

## 3　明确不做的（先说好，免得以后反复讨论）

1. **不建插件系统。** 用户要的是「知道往哪加」，不是「支持第三方 dll 热插拔」。真做插件系统要管：加载器、版本兼容、权限、崩溃隔离——这些现在一个用户都没有。
2. **不把 `Modules` 目录改成真的。** 那个空目录留着无害，但不要因为它存在就硬往里塞东西。**判断标准：如果一个新功能只需要改 1~2 个现有文件，就别新建目录。**
3. **不为了「模块化」给 OCR 加接口。** 三引擎（RapidOcrNet / Windows.Media.Ocr / Tesseract）是**依次兜底**的关系，不是可替换的实现——它们是同一条流水线的三段，拆成接口只会让调用方多看一层还不解决问题。

---

## 4　判断准则（一句话）

**「加新东西」的默认做法是改现有的注入点，不是新建架构。** 只有当你发现必须同时改 3 个以上互不相关的地方、且这些地方以后还要再改，才值得引入一个新的接缝。

现在就 2 个接缝，够用。
