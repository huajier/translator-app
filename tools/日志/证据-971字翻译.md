## 五、`⏎` 劈词的真相（架构师上一轮也夸大了）

全量统计 `tools\日志\历史取词记录\*.txt`：换行总数 **9199**，换行两侧都是字母数字的 **6875（74.7%）**。

但逐个看，绝大多数是**正常折行**，不是劈词：

```
...the gatekeeper refused to | open the gate...     ← 正常：to 在行尾，open 在下一行
...recognition | engine...                          ← 正常：单词整个在行尾
...文档、电子书、票据录 | 入等场景中...              ← 正常：中文任意位置折行
```

**翻译服务对这种换行处理是正确的**（架构师 MyMemory 实测：`refused to\nopen` → 「守门人拒绝\n打开大门」，换行保留、译文正确）。

真正会翻错的是**多列/表格布局被读成一行**，样本：

```
Lord⏎PERKS            135 次   ← 角色名 + 表头，两个独立元素
NOW⏎ON                228 次   ← 两个独立按钮
STABILITY⏎MAGAZINE    132 次   ← 属性名 + 弹匣
```

这类送进翻译必然乱。但它是**版式理解问题**（要判断这一行是不是多列），不是「劈词」问题。架构师上一轮把两者混为一谈，更正。
