## 1　逐条核实（架构师实读，不是转述）

### ① 托盘菜单点外面不关 —— 真 bug，根因确认

`src\TranslatorApp\App.xaml.cs:65` `public partial class App : System.Windows.Application` —— **纯 WPF**。
`grep -rn "AddMessageFilter\|Application.Run\|IMessageFilter" src/ --include=*.cs` → **0 命中**，没有 WinForms 消息泵。

`src\TranslatorApp\TrayIcon.cs:36` `private static ContextMenuStrip? _menu;`、`:238` `_menu.Show(Cursor.Position);`

**为什么会这样**：`ContextMenuStrip` 是 WinForms 控件，它靠「自己是前台窗口」来收 `WM_ACTIVATEAPP`/鼠标捕获，从而知道用户点了别处该关。WPF 应用里没有 WinForms 的 `Application.Run()` 消息循环在跑，`Show()` 之后菜单**没能变成前台窗口**，于是它永远以为「用户还在菜单里」。

**官方修法（WinForms `NotifyIcon` + `ContextMenuStrip` 的标准做法）**：
```csharp
NativeMethods.SetForegroundWindow(ownerHwnd);   // 先在托盘图标所属窗口上抢一次前台
_menu.Show(Cursor.Position);                     // 再弹，菜单才能真正拿到焦点
```
`src\Core\Native\NativeMethods.cs` **目前没有 `SetForegroundWindow`**（`grep` 零命中），要新增一条 P/Invoke。

**【已知副作用，必须写进注释】** 抢前台会让菜单在**第一次**弹出时把焦点从当前程序手里拿走（Windows 的前台锁，最多会闪一下任务栏）。这是 WinForms 这套菜单的固有代价，不是我们的 bug。如果用户觉得闪得难受，替代路是**改回 WPF 原生 `ContextMenu`**（就没有这个问题），但那要重写 `TrayIcon.ShowMenu()` 里的弹法，本轮不顺手做——**先修好，闪一下比点不掉强。**

### ② 翻译默认开启 —— 需求成立，但有个坑用户没看到

`src\Core\Capture\AppSettings.cs:162` `public static bool TranslateEnabled { get; private set; } = false;`
注释写得很硬：「**默认 false = 一个字都不外发**」「用户没主动开之前，程序一次网络请求都不该发」。

**改成 true 有 3 个连带影响，一个都不能漏：**

1. **老配置不会跟着变**。`Load()` 读的是磁盘上存的值，用户这台机器 `%APPDATA%\TranslatorApp\settings.json` 里已经是 `"translateEnabled": false`。**只改代码里的默认值，用户这台老的永远还是关的**。→ 需要一次性迁移（见 §3-②），验收时也必须**删配置模拟新装**再验。
2. **首次提示的触发条件已经对了**。`App.xaml.cs:224` 启动时就调 `EnsureTranslateNotice()`，它内部 `if (!TranslateEnabled || TranslateNoticeShown) return;`（`:243`）。默认 true + 新装 → 会弹。**这块代码一个字都不用改。**
3. **隐私披露的强度要提**。现在那句话是「框选到的文字会发到微软翻译服务。只发文字，不发截图、不发窗口标题、不发进程名。」——在「用户自己点的开关」语境下够用；改成默认开之后，**用户没点任何东西就被外发了**，所以提示必须把「不用你操作已经开着」说明白。建议改成两行：
   > 翻译已经开着：框到的文字会发到微软翻译服务。
   > 只发文字，不发截图、不发窗口标题、不发进程名。关掉在托盘右键菜单。

   同时 `TranslateNoticeShown` 现在是「弹过就永不再弹」，那个语义对「默认关」是对的；默认开之后用户很可能需要重看，但**不许改成每次都弹**（那变骚扰）。**保持弹一次。**

## 4　回答用户：翻译引擎现在有几个，能不能加

**现在只有微软一个**，走的是「Bing 网页翻译」的免密钥通道（`BingFreeProvider`）。它不是公开 API——是微软给自家浏览器用的内部接口，随时可能改或关。

**谷歌有两条路，但都不适合现在：**

| 路子 | 要不要密钥 | 本机能不能用 | 结论 |
|---|---|---|---|
| Google Cloud Translation API（官方） | 要，还要绑信用卡 | 要能连 Google 服务器 | 你说了不申请密钥、不绑卡，暂时排除 |
| `translate.googleapis.com`（网页翻译用的免费接口） | 不要 | ❌ **不可用** | 你的机器 hosts 文件里这个域名被钉在 `127.0.0.1`（被第三方工具改的，不是我们改的），根本连不出去 |

**以后要加，加得进去，而且很便宜**：`ITranslationProvider` 接口就摆在那（`src\Core\Translate\ITranslationProvider.cs:17`），换一个翻译源 = 新写一个类 + 改 `TranslationService.cs:302` 一行。开关、缓存、超时、卡片显示全都不用动。

**但要先说清一件事**：接口能加，不代表「加完就能用」。真加谷歌官方 API 需要：①你去申请密钥 ②绑信用卡（免费额度每月 50 万字符，超了要钱）③本机网络能连 Google。这三样现在一个都不具备。**所以「能加」是架构上的能加，不是今天就能跑的能加。**
