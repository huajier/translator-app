## 2　速度账（分「本地假服务器」与「真 Bing」两列，**这是用户强制要求**）

| 指标 | 本地假服务器（回归用） | 真 Bing（用户实际体验） |
|---|---|---|
| 翻译单项 P50 | **2 ms** | **2070 ms**（≥200 字长文本）／ 969 ms（11 字短串） |
| 翻译单项 P95 | **4 ms** | **2873 ms** |
| 原文可见（认字）P50 / P95 · 回放 | 41 / 250 ms | —（回放不联网） |
| 原文可见（认字）P50 / P95 · **真机** | — | **47 / 656 ms**（n=3088 条真实取词，min 15 / max 7844） |
| 取票（拿 token） | 0（假服务器不需要） | **424 ms**，进程内缓存，只有冷启动第一次含 |

**真机冷启动最坏 = 取票 424 + 翻译 2873 = 3297 ms**；实测五次冷启动 2859 / 2169 / 2083 / 2641 / 2238 ms（275 字），最长 2859，比预估还低一点。

**为什么硬闸是 5000 而不是原来的 2500**：2500 是「用户盯着空白等译文」那个时代定的。改成「原文先出 + 翻译中…」之后用户有东西读，多等两秒不难受；而 3297 的最坏情况扣掉取消余量只剩 2380ms，落在中位数偏下 → 实测 5 次里 4 次超时，症状是「永远看不到译文」。改 5000 后 5/5 成功。**这不是放宽指标，是原来那个数字的前提已经不存在了。**

## 4　明确的边界与已知局限

### 4.1　翻译通道是非官方接口
Bing 网页翻译（`cn.bing.com/ttranslatev3`）**不是公开 API**：没有 SLA、随时可能改协议或直接关掉、按 IP 限流。所以 `ITranslationProvider` 接口必须留着（见 `阶段四-模块化接入点.md`），将来它挂了换一个实现即可，不用改上层。

### 4.2　不做本地语言码校验表
填错语言码 → 必应回 400 → 卡片显示失败原因。这是**有意的**：维护一张码表只会让新语言进来时被挡住。

### 4.3　`translateEndpoint` 不进任何界面
它是测试逃生口（指向假服务器），进了 UI 就变成「用户能把自己配坏」的入口。

### 4.4　两个 P1 没修（不阻断，记着）
- **P1-I1**：「其他…」清空后不填就走，下拉框会空着（配置不会坏，只是界面看着迷惑）
- **P1-I2**：手填只认语言码，普通用户会打「日语」。建议加 ≤10 条中文别名→代码映射（日语→ja、英语→en…），命中就换、没命中照原样送。**不建校验表**。

### 4.5　架构师验不了的（如实交代）
我这边沙箱 `dotnet build` 直接 `MSB3883 / 拒绝访问`，HTTPS 全死（`SEC_E_NO_CREDENTIALS`）。**所以「编译通过」和「真联网能翻」这两条我只能信执行 AI 的日志与截图，无法亲手复现。** 我能验的是：读源码、读日志、读配置、看截图、算数、比对时间戳——这些我都做了，逐条对过，零虚报。

## 5　成品怎么验（给用户）

`release\v1.9\` 是完整的绿色包，双击 `TranslatorApp.exe` 即可，不用装任何东西。

**建议按这个顺序摸一遍（每步 30 秒）：**

1. **看主窗口**：双击托盘图标打开主窗口。应该能看到「怎么用」说明、翻译开关、目标语言下拉框三块。下拉框里 8 种语言 + 「其他…」。
2. **原地取词（不翻译）**：先确认托盘菜单「翻译：把文字发给微软」**没有勾**。随便打开一个英文网页，按住右键框一句 → 卡片只显示英文原文。
3. **开翻译再来一次**：托盘菜单勾上「翻译」。再框一句英文 → 卡片先出原文 + 「翻译中…」→ 一两秒后译文补上。
4. **验同步**：主窗口把开关关掉 → 看托盘菜单里那个勾是不是也没了。
5. **验目标语言**：主窗口选「日语」→ 关掉重开 → 下拉框还是「日语（ja）」。再框一句 → 出来的是日文。
6. **顺手试试不灵的地方**（这是最值钱的，帮我找 bug）：
   - 框一段很长的剧情文本（三四百字）→ 看译文区会不会撑爆卡片、能不能滚动
   - 框中文界面 → 应该不翻译（目标语言是中文时，中文原文不翻）
   - 断网框一次 → 应该显示「翻译超时/失败，原文已保留」，原文一字不丢
   - 把目标语言手填成 `xx-YY` → 应该翻译失败但原文还在（这是**预期行为**，不是 bug）

**遇到不对的，告诉我三件事：** ①框的是什么（游戏名/在哪）②卡片显示了什么（截图最好）③`release\v1.9\logs\` 里最新那个 txt 的最后几十行。有这三样我就能定位。

## 7　这一阶段最值钱的三条教训（写给以后的我）

1. **假服务器会消灭它要测的东西。** T3a-补 的「冷启动 PASS」连着本地假服务器，2ms 返回，不管预算怎么设都不会被饿死——它恰好测不出「预算不够导致一个请求都不发」这个 bug。铁证是译文字数 280 = 原文 275 + 「【假译文】」5 字符。**要测真实体验，就必须打真实通道。**
2. **存了的截图不看等于没验。** 那轮 ⑧ 之所以糊弄过去，正因为图存了没人打开。从这轮起强制：自动截图必须先看过再交，汇报里写「已看图确认」，写不出这句算没验。
3. **工具说的和数字对不上时，先算数再信工具。** 识图说「卡片右侧被屏幕切掉」，日志写 `位置=(952,160) 尺寸=442×259`，952+442=1394 < 1920，数学上不可能出屏——放大复核确认识图错了。**识图适合验证内容（切字、空块、出屏），不适合猜坐标。**
