## 1. Q2 的答案：加密就带不走，这是硬事实

DPAPI（Windows 自带的加密 API）按用户账户派生密钥，**换电脑、重装系统、换 Windows 账户，密文就解不开了**。
这不是实现偷懒，是设计如此——解不开正是它的作用。

所以取舍只有两条：

- **加密**：密钥泄露风险接近零。代价＝换电脑重新填一次（从 Azure 门户复制粘贴，约 10 秒）。
- **明文**：换电脑把 `settings.json` 拷过去就能用。代价＝任何能打开这个文件的人都能看到密钥，共用电脑等于贴在屏幕上。

**架构师建议：加密。** 重填成本 10 秒，泄露成本是别人烧你的额度，两个数量级不对等。

### 1.1 但加密这条路现在有个拦路虎，我已实测解决

`System.Security.Cryptography.ProtectedData` **不在 .NET 10 的框架里**，
官方做法是加 NuGet 包 `System.Security.Cryptography.ProtectedData`。
而本机现在**拉不了新的 NuGet 包**：

```
error NU1301: 无法加载源 https://api.nuget.org/v3/index.json 的服务索引。
  The SSL connection could not be established, see inner exception.
  Authentication failed, see inner exception.
  安全包中没有可用的凭证
```

（现有包全在全局缓存里，所以 `src\` 还能离线还原——但**新加任何包都会失败**。）

**解法（已实测通过）**：直接用 P/Invoke 调 `crypt32.dll` 的 `CryptProtectData` / `CryptUnprotectData`，
约 30 行，零依赖。实测：

```
明文长度=22  密文长度=272  解密回原文=SecretKey_abcd1234EFGH
密文头 4 字节 = 01 00 00 00（标准 DPAPI 格式）
```

→ **不加任何 NuGet 包，Key 也能加密。** 这条写进 T3，不给「以后再说」的余地。

## 2. 「未配置密钥」是一级状态，不是错误

Q1 答「没有密钥」，意味着**绝大多数用户第一次装上就是这个状态**。所以：

- `TranslationFailure` 枚举加 **`NotConfigured`**（与 `AuthFailed` 分开：后者＝填了但不对，前者＝根本没填）。
- 卡片表现：**照常显示原文**，下面一行「翻译未开启：还没填微软密钥（托盘 → 打开主窗口 → 填密钥）」。
- 不得出现「翻译失败」「错误」这种吓人的字眼——用户什么都没做错。
- 日志：`翻译跳过（未配置密钥）`，不打印任何密钥片段（哪怕前 4 位，没配的时候也没有）。

## 3. 一个必须让执行 AI 知道的坏消息：我这边 TLS 是死的

我在沙箱里实测，**本机所有 HTTPS 都连不上**，与网络环境无关：

```
curl.exe https://www.baidu.com  → curl: (35) schannel: AcquireCredentialsHandle failed: SEC_E_NO_CREDENTIALS (0x8009030E)
SslStream(www.baidu.com:443)    → Win32Exception「安全包中没有可用的凭证」
nuget restore                   → 同上
TCP 443 建连                    → 成功 18ms / 152ms（网络本身是通的）
TLS 握手                        → 0ms 就失败
```

根因是我这个沙箱的令牌受限（认证类型 NTLM、只有 10 个组、读不出完整性级别），
**不是用户的网络问题，也不代表 `TranslatorApp.exe` 在真实桌面跑不通**。

**对 T3 的影响**：
- **不影响**——假译服务器是纯 HTTP over TCP，不碰 TLS，T3a 的量测照跑。
- **影响 T6**——「真连 Azure 抽检」这条**我验不了**。必须由执行 AI 在自己环境跑，
  或者用户手动跑一次并把结果贴回来。T6 收口时这一条要单独标出来，不许混在「全 PASS」里。

## 4. 目标语言清单（Q3 定案）

下拉固定 8 项 + 一项「其他…」：

| 显示 | 码 |
|---|---|
| 中文（简体） | `zh-Hans` |
| 中文（繁体） | `zh-Hant` |
| 英文 | `en` |
| 日文 | `ja` |
| 韩文 | `ko` |
| 俄文 | `ru` |
| 法文 | `fr` |
| 德文 | `de` |

「其他…」允许手填语言码。**不做本地校验表**——填错由 Azure 回 `400036`，
我们把它映射成「目标语言代码不认识：`xxx`」。理由：维护一份完整语言码表是纯负债，Azure 已经有一份了。

## 5. T3 切分（放行版本）

**T3a：Provider + Service + 缓存，不碰 UI。**
- `ITranslationProvider` / `AzureTranslatorProvider` / `TranslationService` / `TranslationCache` / `TranslationResult` / `TranslationFailure`（含新增 `NotConfigured`）
- **HTTP 必须 `HttpClient` + `SocketsHttpHandler`**，禁 `HttpWebRequest`（第五轮 §2：Expect 100-continue 每次白等）
- **endpoint 是回环地址时 `SocketsHttpHandler.Proxy = null`**（第三轮 P1-C1：本机 IE 设置 `ProxyServer=127.0.0.1:7890`，公司网络一开就代理住本地回环）
- 密钥来源优先级：环境变量 `TRANSLATOR_API_KEY` > 配置文件
- 加密：`CryptProtectData` P/Invoke，只在配置里存 Base64 密文，前缀 `dpapi:` 标记，读到没有前缀的当明文兼容
- settings.json 新增 5 键（`translateApiKey` 存密文、`translateRegion`、`translateTargetLang`、`translateEndpoint`）

**T3b：主窗口设置区。** 开关 / 目标语言 / 密钥 / 区域。**T3a 的数字出来之前不许动 UI**——
先有干净的基线，才知道 UI 到底花了多少。

**验收（T3a）**：
1. 假服务器 P95（注明「本地假服务器」，不是真实网络）
2. 未配置密钥 → `NotConfigured`，不是异常、不崩
3. 密钥密文落盘后重新读回能解开
4. endpoint 指回环时**不经过 IE 代理**（实测：把系统代理打开，本地调用仍然成功）
5. 缓存第二轮 ≥95% 命中
