## 2. P0-B1（必修）：隐私提示会把刚认出来的字吃掉

`src/TranslatorApp/App.xaml.cs:239` 的 `EnsureTranslateNotice()` 复用 `_activeToast`（:248-256）：
```
if (_activeToast is not null && _activeToast.IsVisible) { _activeToast.ShowNotice(title, detail); }
```
而 `_activeToast` 在 `src/TranslatorApp/App.xaml.cs:648` 被赋成**刚出结果的取词卡片**。

走一遍真实流程：框选 → 卡片显示识别结果（正在读）→ 点托盘开翻译 →
`ShowNotice` 把 `MainText.Text` 清空、`MainText.Visibility = Collapsed`（`src/UI/Shared/DebugToastWindow.xaml.cs:348-354`）→
**用户正在读的识别结果消失，标题换成「要开始翻译了」**。

这正好发生在「第一次开翻译」那一刻，也就是用户刚试完识别、最能感觉到「我的字没了」的时候。

**改法（一处修两边，净减行数）**：在 `App.xaml.cs` 加一个
```csharp
private static void ShowTransientNotice(string title, string detail)
{
    try
    {
        var notice = new DebugToastWindow();
        notice.ShowNotice(title, detail);
        _activeToast = notice;
    }
    catch (Exception ex) { AppLogger.Warn($"屏幕提示没显示出来：{ex.Message}"); }
}
```
`ShowDebugNotice`（:487）与 `EnsureTranslateNotice`（:239）都改成调它，删掉两处复用分支（:248-256、:496-504）。
`Ctrl+Alt+D` 那条（现在也有同样的隐患）顺带修掉。

## 7. 口径变更 2：`from` 不传，缓存键 =（规范化文字, 目标语言）

用户 Q1 原话：「让用户选择一种语言，然后**除了这种语言外识别出来的所有都翻译**」。
本地 `LanguageDetector` 只有三档（中文 / 俄文 / 外文-拉丁），**判不出英法德日**，
硬传 `from` 等于把「全都翻」砍成「只翻这三种」，而且传错源语言 Azure 译得更差。

所以：**不传 `from`，用 Azure 的自动检测**（省略该参数即自动检测，计费不变）；
源语言只用本地三档做一件事——**判断「是不是用户选的母语」，是就不翻**。
Azure 返回的 `detectedLanguage` 记进 `TranslationResult` 供展示/诊断，**不进缓存键**。

缓存键相应改回 `SHA256(规范化文字 + "|" + 目标语言)`（这是对上轮「from/to 都要进键」的**自我修正**）：
- `to` 必须进键——用户改了母语就得重翻，否则命中旧译文；
- `from` 不进键——它恒为自动检测，且同一段文字翻成同一语言结果唯一，正好就是用户 Q2 拍板的「只按文字内容判」。
