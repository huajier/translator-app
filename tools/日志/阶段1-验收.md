## 四、本次阶段的真 Bug：托盘图标挂不上（已定位并修复）

这是用户反馈的「A 还是没有（图标）」的根因，写在这里存证：

**现象**：程序在跑、日志说在尝试挂图标，但通知区域里就是没有；日志里是 `NIM_ADD=失败`、`GetLastError=5`（拒绝访问）。

**排查过程（证据链）**：

1. 结构体大小一致（976 字节）、窗口句柄一致、图标句柄有效 → 不是代码写错；
2. 同样的调用在 PowerShell 里**成功**，在程序里**失败** → 差别只能是**权限**；
3. 程序内诊断显示：`WM_NULL`（权限门槛低的消息）能送达，`NIM_ADD` 被拒 → 典型的 Windows **UIPI**（低权限进程不许给高权限窗口发消息）；
4. 用 `icacls` 查文件，发现 exe 上带 `Mandatory Label\Low Mandatory Level` —— **文件被打了「低完整性」标签**，从它启动的进程就被钉在低权限上；
5. 把标签去掉后重新发布：进程权限升到与任务栏一致，**托盘数量 +1，`NIM_ADD=成功`**。

**修复方式**（已写进 `tools\脚本\构建.ps1` 第 3 步，以后每次发布自动做）：

```
SetNamedSecurityInfoW(路径, SE_FILE_OBJECT, LABEL_SECURITY_INFORMATION, NULL, NULL, NULL, NULL)
```

**防复发**：日志里保留了权限诊断行 —— 以后万一再挂不上，日志会直接打印「本程序权限 / 系统任务栏权限」，一眼看出是不是又中了标签。

### 附：第二个坑 —— 发布目录里的图标被 `dotnet publish` 偷偷删掉

**现象**：明明编译成功了，程序却在日志里写

```
[WARN] 托盘图标文件不存在，改用系统默认图标：...\release\v0.1\assets\tray.ico
[INFO] 托盘图标已挂上通知区域（第 1 次尝试）：... hIcon=0x1002B ...
```

`hIcon=0x1002B` 是系统默认白图标 —— 也就是说**图标白做了**。

**排查**：连续跑 3 次 `dotnet publish`，每次 `release\v0.1\assets\` 都变成空目录。
原因是 MSBuild 发布时的**增量清理**：它把上一次发布的文件清单拿来做差集，把「本次没重新复制的」当作过期文件删掉 —— 而这个 ico 恰好每次都落在差集里。
试过给 csproj 加 `CopyToPublishDirectory=PreserveNewest`，**拦不住**。

**修复（两道保险）**：

1. csproj 里加 `AfterTargets="Publish"` 的补偿目标：**发布动作结束之后**再强制写一次 `assets\tray.ico`；
2. `tools\脚本\构建.ps1` 第 3.5 步：发布完检查这个文件，**缺了就补、补不上就报错退出**（不让坏产物蒙混过关）。

**验证**：连续 3 次裸跑 `dotnet publish` + 跑一遍 `构建.ps1`，`tray.ico` 全程都在；
程序日志回到 `托盘图标来源：...\assets\tray.ico` + `hIcon=0x15671C4F`（**不是** `0x1002B`），托盘计数 +1。

## 五、我怎么测的（你可以照着复现）

在项目根目录打开 PowerShell：

```powershell
# 一键编译 + 去标签 + 确认 exe 存在
powershell -ExecutionPolicy Bypass -File "tools\脚本\构建.ps1"

# 数托盘图标（只数，不启动）
powershell -ExecutionPolicy Bypass -File "tools\脚本\托盘检查.ps1"

# 自动启动程序、数启动前后差值（差值为 1 = 通过）
powershell -ExecutionPolicy Bypass -File "tools\脚本\托盘检查.ps1" -Launch
```

> **为什么都要加 `-ExecutionPolicy Bypass`**：这台电脑的 PowerShell 默认禁止直接运行 `.ps1` 脚本，不加这一段会弹「禁止运行脚本」的红字。这不是程序的问题，是系统策略。
