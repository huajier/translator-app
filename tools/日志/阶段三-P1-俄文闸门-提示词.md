**不是分数低、不是阈值没调对**。这解释了用户实测「英文能认、任何长度的俄文都乱码、切 tesseract 就好」。

### §0.2 用户原方案为什么**不能直接照做**（必须先讲清楚再动手）

用户给的方案是：「调 RapidOCR **之前**，先算待识别文本的西里尔字母占比，超阈值就跳过 RapidOCR」。

我把这个前提拿到真日志里量了（`app-20261109.log`，2231 次取词）：

| 量 | 数字 |
|---|---|
| 判为俄文的取词次数 | 267 |
| 其中「调 RapidOCR 之前手上那段文本」（Windows 第一遍）**含西里尔字母**的次数 | **0** |
| 其中第一遍文本几乎为空（有效字符 < 2）的次数 | 194（72.7%） |
| 非空样本长这样 | `二 [ 是 3T/X MR 「 K/X ØpaHUY3CKMX O 〖 8 诟》` |

**根因**：`OcrTextCapture.RunForeignPath` 被调用时，手上只有 **Windows 自带 OCR 的第一遍文本**
（`OcrTextCapture.cs:360` 传入的 `text`）。Windows 中文引擎**读不出西里尔字母**（本项目早已知：
`EngineBenchmark.cs:772` 记录「本机 Windows OCR 根本没装俄文识别包」），
所以那个变量里**永远是拉丁/符号噪声，西里尔占比恒为 0**。
按用户原方案写，闸门**一次都不会触发**，等于白改。

→ 所以要保住用户的**意图**（俄文别走 RapidOCR），但把**判据换到能拿到的信号上**：
**不猜语言，改成「RapidOCR 吐出来的东西像不像俄文」+「它自己有多不自信」**。

## §1 要你做什么（一句话）

在 `src\Core\Capture\OcrTextCapture.Foreign.cs` 的 RapidOCR 采纳分支里加一道**确认式闸门**：
**先看 RapidOCR 自己的输出像不像乱码；像，才多跑一次 Tesseract；只有当 Tesseract 的结果被验明是「真俄文」时才替换，否则原样保留 RapidOCR 结果。**

**核心安全性质：这道闸门最坏只会让结果变慢，不会让结果变差。**
换不换由「Tesseract 那份是不是真俄文」决定，不是由「RapidOCR 那份是不是乱码」决定。

### §2.2 改法（伪代码，**不是**让你照抄成 C#）

在 `:93` 那个 `if` 里面、`:119` 的 `return` **之前**插入：

```csharp
// 1) 判断这次要不要"怀疑"
bool suspect = LooksNotCyrillic(rapidText) || rapidScore < RapidOcrCyrillicConfirmScore;

// 2) 怀疑才算，且只算一次
if (suspect)
{
    // 3) 复用旧通道：把上面那套 Tesseract 路走一遍，拿到它的文本
    //    （见 §2.3 —— 不要复制粘贴旧通道代码，要抽成方法后两边共调用一次）
    //    🔴 传 raw，**不是** rapidInput：旧通道吃的是 UpscaleForForeign(raw)，
    //       传 rapidInput 在 RapidOcrUseOriginal=true 时会喂反色图，
    //       拿到的就不是「关掉开关用户会得到什么」，确认结论失效。
    if (TryRecognizeRussianForConfirm(raw, out string ruText, out string ruNote))
    {
        // 4) 验明真俄文才换
        if (LanguageDetector.CountCyrillicRatio(ruText) >= MinCyrillicRatioForRussian
            && LanguageDetector.CountCyrillicHomoglyphRatio(ruText) < MaxCyrillicHomoglyphRatioForConfirm)
        {
            // 换成 ruText，channelUsed = "Tesseract"（如实写，不许张冠李戴）
        }
    }
    // 5) 验不过 → 什么都不做，rapidText 原样返回
}
```

**必须遵守的三条：**

1. **`MinCyrillicRatioForRussian`（0.50）直接复用现成常量**，不许新造一个。位置：`OcrTextCapture.Tuning.cs:122`。
2. **同形字护栏必须取 `0.50`，不能用现成的 `MaxCyrillicHomoglyphRatioForRussian`（0.75）。**
   这是本方案唯一一个有实测分界线的参数，理由见 §2.4。**要新增一个常量**（如 `MaxCyrillicHomoglyphRatioForConfirm = 0.50`），
   并在注释里写清「为什么和上面那个 0.75 不是一个数」——否则下一个人一定会想合并。
3. **`channelUsed` 必须如实反映来源。** 用了 Tesseract 的结果就写 `"Tesseract"`，
   否则界面和日志会说谎，以后每次核对都要重新怀疑一遍。

### §2.3.1 两条硬约束（架构师 2026-11-09 12:55 补，踩了就白干）

1. **确认方法里必须先 `TesseractOcr.EnsureInitialized()`。**
   现在 `:136` 那个 `EnsureInitialized()` 在 RapidOCR 块**之后**，
   你要在它之前就调 Tesseract，自己得先把引擎备好。
   **时序坑**：语言引擎是懒建的（`TesseractOcr.cs:623` 的说明），
   `rus` 第一次调用要付 200~300 ms。所以
   **第一次取词会明显慢**，这是预期的，不要为了「抹平」去启动时预建引擎（那是动全局）。
2. **确认方法吃的图必须是 `UpscaleForForeign(raw)`，不是 `rapidInput`。**
   旧通道从 `:183` 起吃的是放大 4 倍的 `raw`；
   `rapidInput` 在 `RapidOcrUseOriginal=true` 时是**原图**、`false` 时是**反色图**。
   拿`rapidInput`去确认，等于问「反色图丢给 Tesseract 会怎样」——
   那不是用户关掉开关时会得到的结果，确认结论不成立。
   **正确写法：方法签名收 `Bitmap raw`，进去自己 `UpscaleForForeign(raw)`。**

### §2.4 为什么同形字护栏是 0.50 而不是 0.75（这是本方案的实测分界线）

`Tuning.cs:142` 那个 `0.75` 是给「Tesseract rus 票直接采纳」用的老场景。
**新闸门场景不同**：它要去拦的是「RapidOCR 把英文按字母形状拼成假俄文」。

拿真数据扫阈值（`tools\脚本\P1-俄文闸门-证据.py` 第 ④ 节最后一行，其余参数固定为推荐的 ③）：

| 同形字阈值 | 段级 | 俄文段 | 行级 | 行级丢失 |
|---|---|---|---|---|
| **0.50（本方案取值）** | 48/56 | 10/11 | **56/80** | **无** |
| **0.75（沿用现值）** | 48/56 | 10/11 | **55/80** | **行-60** |

**行-60 是怎么死的**：真值 `SG-225 'Breaker'`，RapidOCR 读对，
Tesseract rus 读成 `SG-225 'ВгеаКег` —— 西里尔占比 0.78（过得了 0.50 的西里尔闸门），
但同形字占比 **0.71**，正好卡在 0.75 底下、0.50 上面。**0.50 能拦住它，0.75 拦不住。**

（0.50~0.70 之间没有别的样本，取 0.50 与取 0.70 效果相同；取 0.50 是**贴着已有实证**走：
`Tuning.cs:138-139` 记录「0.50 起就零误伤真俄文（2178 个真俄文块）」）。

### §3.1 「词内数字字母混排」怎么算（这是本方案唯一的新逻辑）

把待判文本按空白切词，只保留含字母的词，统计其中**同时含数字和字母**的占比。

- RapidOCR 把俄文硬拼成拉丁时，产出的典型形态是 `3b`、`p3`、`4a`、`Apyro`、`Mae`、`B3noMa` —— **数字和字母糊在一个词里**；
- 真英文/真俄文的词几乎不会这样（`2,5 МБ`、`404`、`DEX 0`、`SG-225` 里数字都是**独立词或带分隔符**）。

实测分界（同一批回放，`tools\脚本\P1-俄文闸门-证据.py` 第 ⑤ 节）：

| 语料 | 该比例 P50 | P90 |
|---|---|---|
| 俄文段 | **0.250** | 0.500 |
| 非俄文段 | **0.000** | 0.222 |

**在行级 80 张英文 UI 图上，该判据只触发 9/80（11%）。**

> 实现位置建议：`LanguageDetector.cs` 里**已经有** `CountCyrillicRatio` / `CountCyrillicHomoglyphRatio` /
> `CountLatinRatio` 三兄弟。按 `制作流程-AI版.md` §九 最后一条「写新函数前先搜一遍」，
> **先确认没有现成的**，再决定加在 `LanguageDetector`（推荐，它管字母统计）而不是塞进 `OcrTextCapture`。

### §3.2 为什么分数判据是 0.95

同一批数据里 RapidOCR 采纳样本的分数分布（`P1-俄文闸门-证据.py` 第 ⑥ 节）：

| 语料 | n | P10 | P50 | P90 |
|---|---|---|---|---|
| 俄文段 | 9 | **0.63** | **0.82** | 0.90 |
| 非俄文段 | 33 | **0.80** | **0.97** | 0.99 |

（俄文段里 `材料2-R1`、`材料2-R6` **根本没进 RapidOCR 通道**，所以没有分数——
这两段本来就回退去了 Tesseract，闸门对它们无能为力，也不需要。）

`< 0.95` 能捞到 9/11 俄文段，在 80 张英文行图上触发 17/80（21%）。**分数单独用不如 ① 精准**，
但两者**互补**（① 靠形状、② 靠自信度），合起来俄文段从 2/11 → **10/11**。
