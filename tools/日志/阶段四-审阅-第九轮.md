## §2 P0（阻断，修完才能收口）

### P0-E1 目标语言一旦不是中文，「母语不翻」就死锁

- 位置：`src/Core/Translate/TranslationService.cs:97`
  `if (LanguageDetector.Detect(text) == LanguageDetector.Chinese) return Disabled;`
- 问题：这里**硬编码**判「是不是中文」，但目标语言 `AppSettings.TranslateTargetLang` 是**可配的**（T3b 马上要给它做下拉）。
  用户把目标语言选成英文/日文后：
  - 中文原文 → 判成 Chinese → **永远不翻**，用户选的目标语言等于没选；
  - 这条不是边缘情况，是**功能死锁**：学中文的外国人、想把中文界面翻成英文的用户，一选就全废。
- 违背用户原话（m00038 Q1）：「让用户选择一种语言，然后**除了这种语言外**识别出来的所有都翻译」——
  是「除了目标语言」，不是「除了中文」。
- 改法（最小正确解，不扩 `LanguageDetector`）：
  ```csharp
  // 只有目标语言是中文时，本地中文判据才有意义。
  // 其他目标语言我们判不出来（Detect 只有 Chinese/Russian/Foreign 三档），
  // 一律交给服务端自动检测 —— 宁可发出去让 Bing 判，也不要本地猜着跳过。
  static bool IsChineseTarget(string to) => to.StartsWith("zh", StringComparison.OrdinalIgnoreCase);
  if (IsChineseTarget(target) && LanguageDetector.Detect(text) == LanguageDetector.Chinese)
      return Disabled;
  ```
- 已知代价（明确接受，写进注释）：目标语言=英文 + 原文本来就是英文时，会白发一次请求、拿回原文。
  代价是「多烧一次额度、多花几百毫秒」，收益是「中文原文能翻成英文了」。**这个交换必须做**。
- 为什么必须是 P0：T3b 做的就是目标语言下拉，UI 上线那天这个 bug 就活了，而且用户不会报「翻译没生效」——
  他会以为是自己选错了。**先修逻辑，再做 UI。**

### P0-E2 译文区没有高度上限，长译文会把卡片撑出屏幕

- 位置：`src/UI/Shared/DebugToastWindow.xaml:81-88`
  ```xml
  <Border x:Name="TransSep" Height="1" ... />
  <TextBox x:Name="TranslationText" ... TextWrapping="Wrap" MaxWidth="420" ... />
  ```
- 问题：`TranslationText` 只限了 `MaxWidth`，**没有任何 `MaxHeight`，也没进 `ScrollViewer`**；
  而原文 `MainText` 是套在 `TextScroll`（ScrollViewer）里的。
- 后果：一次整块最坏 300 字符（方案 §1 自己写的），译文按 420px 宽折行 ≈ 10~14 行 ≈ 250~350px，
  加原文区（上限 80px）+ 详情行 + 内边距，卡片会顶到屏幕外：**详情行和「失败原因」看不见，
  卡片会被 `PlaceBesideSelection()` 摆到屏幕外，用户以为程序没反应。**
- 为什么 S1~S6 没抓到：假服务器返回的是 `【假译文】` + 原文，最长一条 145 字，还在屏幕内；
  真 Bing 翻一段剧情文本立刻超。
- 改法：把译文区套进 ScrollViewer，`MaxHeight` 取 200 左右（原文 80、译文 200，一屏最多 280px 正文）。
  ```xml
  <ScrollViewer x:Name="TransScroll" MaxHeight="200" VerticalScrollBarVisibility="Auto"
                HorizontalScrollBarVisibility="Disabled" Visibility="Collapsed">
      <TextBox x:Name="TranslationText" ... />
  </ScrollViewer>
  ```
  显隐跟着动（`TransScroll` 和 `TransSep` 一起显隐，`TranslationText` 不再单独管 Visibility）。
  顺带：`needScroll` 那条「可以滚」的提示现在只管原文，译文能滚了要各自说，别混。

### P0-E3 旧的 T1a 验收脚本已经过期，谁跑谁抹掉用户配置

- 位置：`tools\脚本\验收-T1a-开关.ps1:66-75`（`Reset-Settings` 写 **10 键**）与 `:132`（断言 `keys.Count -eq 10`）
- 问题：`AppSettings.Save()` 现在是 **12 键**。脚本是**直接 `Set-Content` 覆写整个文件**，不是走 `Save()`：
  跑一次 = `translateTargetLang` / `translateEndpoint` **被删掉**；`:132` 那条「正好 10 个键」的断言从此永久 FAIL。
- 后果链：T3b 上线后用户改过目标语言 → 下次谁跑一遍 T1a 回归 → 用户设置静默回默认 → 用户不会说「脚本干的」，
  只会说「这软件设置自己会变」。
- 改法：脚本补两键（`translateTargetLang = "zh-Hans"`、`translateEndpoint = ""`），断言 10→**12**，
  注释里的「10 个键」全文改 12。**这条和 T3a 无关，但现在不改就等着踩。**

### P0-E4 真 Bing 零验证，且 `fromLang` 字段名与 T3-spike-2 原始报文自相矛盾

- 位置：`src/Core/Translate/BingFreeProvider.cs:229`
  ```csharp
  string form = "fromLang=auto-detect" + ...
  ```
  注释（:227-228）：「字段名是 fromLang（**实测**），不是 from」
- 矛盾点：T3-spike-2 汇报（m00701）原话是
  `POST https://cn.bing.com/ttranslatev3?isVertical=1 body from=&to=zh-Hans&text=&token=&key=` —— **写的是 `from=`**。
  代码里注释说「实测是 fromLang」，但**没有任何一份留档能证明**。
- 为什么本地全绿不算数：假服务器 `:280` `Get-FormValue -Key 'fromLang'` **只读出来打印，不校验**。
  代码送 `from=`、送 `fromLang=`、送 `乱写=`，假服务器**全都回 200 「【假译文】…」**。
  → S1~S6 六条验收，**没有一条能证明这个字段名是对的**。
- 后果：字段名错的唯一表现是真机上 `statusCode:400`，而降级路径设计得很稳（只显示原文 + 一行「翻译服务没接受这段文字」），
  用户看到的是「翻译老是失败」，我们看不到任何崩溃 —— **这种 bug 最难被报上来。**
- 要求：执行 AI 有 HTTPS 出网能力（T3-spike-2 拿到过 1756/405/768ms 真数字，我在沙箱里做不到），
  **用真 Bing 打一次端到端**，把下面四样原样贴回：
  1. 发出的完整请求行（URL + query）和完整表单 body（token/key 可打码，但**字段名一个字不能改**）；
  2. 响应 HTTP 状态码 + 完整 body（含 `statusCode`、`translations`、`detectedLanguage`）；
  3. 一次成功、一次故意把 `fromLang` 改成 `from` 的对照（证明哪个对）；
  4. 真 Bing 的**翻译单项耗时**（不是端到端），P50/P95 至少各 5 次。
- 这条是**整个 T3a 的地基**。地基没验，上面六条验收全是自证。

### P1-E3 等翻译的那 2.5 秒，卡片完全不动

`RunCaptureAsync` 里认字完成到译文到手之间最长 2.5 秒（S3 实测 2395ms），期间卡片停在 `ShowFor` 的坐标状态，

最小改法：await 之前 `card.ShowTranslating()`（一行，把译文区显示成「正在翻译…」），失败/成功都覆盖掉。
不做也行，**但要在方案里写一句「已知不做」**，别让它变成没人记得的空白。

## §4 架构师自我修正：撤销第一轮 P0-4

第一轮 P0-4 要求「四类失败文案都要补『请重新框选』」。**这条在现在的通道上不成立，撤销。**

理由：翻译失败时**原文已经完整显示在卡片上**，用户要的东西已经到手；重新框选同一块 = 同一段字 = 还是翻不了。
「请重新框选」只对**认字失败**有指导意义（换个框法可能认得出）。硬加在翻译失败上是把用户往一条走不通的路上指。

现在的文案（`TranslationFailure.cs:60-73`）措辞是对的，只按 P1-E1/P1-E2 改两处即可。
