# 03 · 操作手册 — 怎么指挥 AI 做这次优化（照着念就行）

> 这份是**给你（用户）看的**。你不需要懂代码、不需要看代码。
> 你全程只需要做三件事：**复制粘贴指令、看两三个数字、最后框 28 段测试**。
> 全程原则只有一条：**一次只让它做一步，做完汇报，你看过再让它做下一步。**

## 第一关：文档拆分（progress.md 瘦身）

### 1-1 开新对话，先发这段（直接复制）

```
请先读 progress.md 和 制作流程-AI版.md，再读验收日志的最后一节。
然后读 tools\归档\翻译软件优化方案\ 里的两份：01-方案A-代码拆分.md、02-方案B-progress文档拆分.md。
头号规矩：没有我点头，不准回退、不准换引擎、不准做大改动。
今天先做「文档拆分」（方案B）。你通读完方案B 之后，用「先结论后展开」的格式告诉我：
①你打算怎么做 ②要动哪些文件 ③做完怎么验证。
先别动手，等我回复「开始」。
```

**AI 应该回什么**：一段说它读完的汇报，最后**等你批准**（不会直接动手）。
**你检查**：它有没有说"先别动手/等你批准"的意思？有 = 对。如果它直接开始改文件 = 不对，发下面这句：

```
停。我说了先别动手。重新汇报一遍计划，等我批准。
```

### 1-2 批准，让它做

```
开始。按方案B 的「五、执行步骤」做，4 小步一步别跳。
成品文件在 tools\归档\翻译软件优化方案\04-新文档成品（可直接拷贝）\ 里，直接放置，不要自己重写内容。
做完汇报：①progress.md 现在多少行（原来 946 行）②两个新档案文件建了没 ③抽查了哪几行、对不对 ④tag 打了没。
```

**AI 应该回什么**：`946 行 → 358 行`、两个新文件就位、抽查通过、两个 tag 打好。
**你检查**：只要它说"抽查通过、tag 已打"就放行。（想眼见为实：打开项目根目录，看 progress.md 是不是变短了。）

> ✅ 第一关过了之后，**以后的每轮它都会按新规矩记账**——这就是"治本"。

## 第二关：代码拆分（OcrTextCapture.cs → 7 个文件）

> 一共 6 步（第 0 步~第 5 步）。**每一步的指令长得几乎一样，只有"第 X 步"不一样。**
> 建议节奏：第 0~2 步一口气做完；第 3、4 步各做一次；第 5 步单独做（最后要你测试）。

### 2-0 先做"第 0 步：地基"

```
继续方案A（代码拆分）。先做「第 0 步：地基」，不要改任何代码：
① git 确认干净并打 tag「V0.3.3.0-大拆分前」 ② 跑一次构建确认是绿的 ③ 跑三套探针、把基线数字记下来 ④ 汇报。
```

**AI 应该回什么**：tag 打好了、构建"0 错误 0 警告"、三套探针的数字（比如"六段合计 72 条全过"）。
**你检查**：**看到"0 错误 0 警告"**就放行。

### 2-1 ~ 2-4 每一步都用这个模板（复制后把括号里的换掉）

```
继续方案A。做「第 1 步：工具、裁决规矩、常量搬家」。只做这一步，做完停下汇报。
汇报必须回答四个问题：
① 构建多少错误、多少警告？
② 三套探针过没过（对着第 0 步记的基线）？
③ git diff 通读的结论：是不是"只搬家、没改逻辑"？
④ 这一步有没有改任何判断逻辑？（应该回答"没有"）
```

第 2 步换成：`「第 2 步：把"第一遍"抽成方法，搬进 FirstPass 文件」`
第 3 步换成：`「第 3 步：外文方向整体搬家」`
第 4 步换成：`「第 4 步：中文方向整体搬家」`

**AI 应该回什么**：四个答案 + 一句结论（"这一步过了，可以继续"）。
**你检查**：
- ① **必须是"0 错误 0 警告"**（有警告也让它先处理）；
- ② **必须是"全过"**；
- ④ **必须是"没有改逻辑"**。
- 三个都对 → 回它一句 `好，继续下一步`。
- 任何一个不对 → 看下面「出问题怎么办」。

### 2-5 最后一步（要你上场了）

```
做「第 5 步：收口」。做完先停，然后告诉我：我接下来要测什么、怎么测、测完你拿什么算成绩。
```

**AI 应该回什么**：让你打开 `tools\素材\快测材料.html`，用软件框 28 段，框完说"测完了"。

**你测试的操作步骤**（和平时一样，别紧张）：
1. 打开 `tools\素材\快测材料.html`（浏览器里打开）；
2. 打开翻译软件（AI 会让你启动，或者它自己启动好）；
3. 按住 `Ctrl+Alt` 用鼠标框选，**只框灰色小标签下面的字**，一页 28 段都框一遍（顺序随便，漏一两段不扣分）；
4. 框完，对 AI 说：

```
测完了。
```

**AI 应该回什么**：跑 `比对成绩.ps1` 给你成绩单，比如"28/28、判错 0 段"。
**你检查**：**成绩和拆分前一模一样（之前是 28/28）** → 说：

```
过了。把这次整理写进 progress 和验收日志，然后停。
```

如果成绩掉了 → 别急，见下面「出问题怎么办」第 2 条。

## 出问题怎么办（四种情况，照抄就行）

**① AI 说"编译不过"或者"探针没过"：**
```
停，不要继续下一步。按项目规矩先查病根：是搬家搬错了还是别的。
如果你查完发现要"顺手修点别的"，先给我提变更申请单，等我点头。这轮只许搬家。
```

**② 你测出来成绩掉了（比如 26/28）：**
```
停，这轮不继续了。给我两样东西：
① 拆分前 vs 拆分后的成绩对比；② 你翻旧日志、对着同一段核过之后的判断。
先翻旧日志，别先编解释。要不要回退你提建议，我来定（不许自己回退）。
```
> （这是你们的老规矩：先翻旧日志对同一段，再下结论——以前吃过"量具骗人"14 次的亏。）

**③ AI 说"我顺手把某个小问题也改了吧"：**
```
这轮只搬代码，别的先不动。你说的那个记进「未完成代办」，以后再单独做。
```

**④ 同一个问题它修了 3 次还没好：**
```
停。按铁律：把试过什么、有什么证据、还剩哪些办法列给我，用大白话讲。我来拍板。
```

**⑤ 它问"要不要升版本号？"：**
```
不升。按 RULE 4，这种随时能退回去的改动只打 tag、不升版本号。
```

## 全部做完后（收尾三件事）

1. 让 AI 说一遍"现在代码怎么分家的"，你只需要听个大概（例如："以后加语言 = 加一个文件 + 注册一行"）；
2. 让它在 `progress.md` 的「★ 当前状态」里按**新规矩**更新一块（整块替换）；
3. 这份操作手册和方案文件**留在 `tools\归档\` 里不用删**——下次想加语言时，让 AI 翻 01 方案第五节（"以后怎么加新语言"）。
