### 0.6 每阶段的通用流程（原文第 7 章，逐阶段执行）

```text
1. 备份当前可用版本到 翻译软件\backup\阶段N\      ← R8
2. 复述本阶段目标（用 3 句话）
3. 列出本阶段的决策点，等用户选择 ★必停★          ← R1 / R2
4. 说明「我要改哪些文件、改完什么效果」            ← R7
5. 写代码
6. 自测（跑一遍本阶段的测试清单）
7. 交给用户验收（附测试步骤 + exe + 证据）
8. 用户确认通过 → 打版本号 → 更新 docs\更新日志.md
9. 进入下一阶段
```

**绝对不许做的事（全局版，原文 7.3，逐阶段复用）**

| 禁止 | 原因 |
|---|---|
| ❌ 跳过决策点自己选 | 用户要的是「我选的软件」，不是「AI 觉得好的软件」 |
| ❌ 偷偷降级需求 | 做不到就说做不到，给替代方案 |
| ❌ 在 `翻译软件\` 里放临时脚本 | 硬性要求 3（路径基准见 0.1） |
| ❌ 把 API Key 硬编码进代码 | 安全问题 |
| ❌ 交一个「理论上能跑」但没测过的版本 | 没验证 = 没做完 |
| ❌ 一次改一大堆东西 | 出问题无法定位；每轮只改一件事 |
| ❌ 用「应该可以」「大概没问题」来交付 | 要么验证过，要么明说没验证 |
| ❌ 在前一个阶段没验收通过时开始下一阶段 | 地基不稳，越往上越危险 |

**遇到做不到的事的处理方式**：① 明确说「做不到，原因是 X」（X 要说人话）→ ② 给出 2-3 个替代方案，每个说明代价 → ③ 等用户重新选 → ④ 不许自己拍板，不许装没看见。

## 阶段 0 · 开工准备

### 技术目标

在用户的电脑上把「写代码的工具链」装齐并验证通过：装好 .NET 10 LTS **SDK**（不是 Runtime）与 IDE，能用 `dotnet --version` 拿到版本号，能编译并运行一个 WPF 空白窗口程序，并建立规范的文件夹结构。**这一阶段不写任何翻译相关代码。** 验收以「命令行有版本号输出 + 空白窗口能弹出来 + 文件夹结构合规」这三个现象为准。

### 前置依赖

- 前置阶段：无（本项目起点）。
- 必须先由用户选定的决策点：**0-1（开发工具）**、**0-2（.NET 版本，已确认 .NET 10 LTS，仍须让用户确认一次）**、**0-3（代码备份方式）**。三项未确认前，不许开始安装与建目录。

### 关键实现要点

阶段 0 的活主要由**用户手动操作**，AI 的职责是给出精确指令、收集结果、判断是否达标。以下每一步都必须给出可直接照做的文字指令。

1. **检查系统版本**：指导用户 `Win + R` → 输入 `winver` → 回车，确认是 Windows 10 或 11，并记下版本号（如 22H2、23H2），写进 `翻译软件\tools\日志\环境信息.md`。
2. **检查是否 64 位**：`Win + I` → 「系统」→「关于」→ 找「系统类型」，应为「基于 x64 的处理器」；不是 64 位则停止项目并说明不支持。
3. **下载安装开发工具**（按 0-1 的选择给指令）：
   - 选 A：`visualstudio.microsoft.com/zh-hans/` 下载 Community 版，安装时**只勾选「.NET 桌面开发」**（别全勾，否则要装 50 GB）；
   - 选 B：`code.visualstudio.com` 下载，装完后在扩展商店搜「C# Dev Kit」安装；
   - 选 C：`jetbrains.com/rider/` 下载。
4. **安装 .NET SDK**（按 0-2 的选择）：去 `dotnet.microsoft.com/download` 下载对应版本的 **SDK**（是 SDK，不是 Runtime），双击安装一路「下一步」，不改任何选项；**安装包必须存到 `翻译软件\tools\安装包\`**。
5. **验证安装**：`Win + R` → `cmd` → `dotnet --version`，显示出 `10.x.x` 即成功；显示「不是内部或外部命令」则回到第 4 步重做。再用 `dotnet --list-sdks` 确认列表里确实有该 SDK。
6. **建立文件夹结构**：在 `D:\111Desktop\deepseek\翻译软件\` 下新建 `src`、`docs`、`release`、`backup`、`assets`，并确认 `翻译软件\tools\`（含 `安装包\脚本\素材\日志\归档\`）已就位。
7. **写环境检查脚本** `翻译软件\tools\脚本\环境检查.ps1`：把系统版本、SDK 列表、磁盘空间、显示器与缩放比例一次性采集出来，输出直接可粘进 `环境信息.md`——后面阶段 2（坐标）、阶段 9（打包）、阶段 11（本地模型可行性）都要回看这份记录。
8. **建 `.gitignore`**（0-3 选 B/C 时）：`bin\`、`obj\`、`release\`、`backup\`、`*.user`、密钥类文件必须排除；按隐私要求**配置文件与 API Key 绝不入库**。
9. **初始化备份机制**（0-3 选 B/C 时）：给出 3-5 条现成命令（`git init` / `git add .` / `git commit -m "阶段N完成"`），让用户复制粘贴即可，并约定「每阶段验收通过后打一个存档点」。
10. **收集第 9 章的开工确认答复**：把用户回复（决策选项 + 电脑配置 + 屏幕情况 + 用途 + Key 状态）原文记入 `翻译软件\tools\日志\环境信息.md`，后续阶段一律引用这份记录，不许凭印象。
11. **本阶段只做环境**：不许创建 `TranslatorApp` 工程、不许引入任何 NuGet 包、不许写任何业务代码——「先跑通 Hello World」的意义就在于把工具链的坑提前踩完。

### 必须实现的异常处理

| 异常场景 | 期望行为 | 不允许的表现 |
|---|---|---|
| 装的是 Runtime 不是 SDK | `dotnet --version` 报错或版本不符时，明确提示「装错成了 Runtime，请重新下载文件名含 SDK 的安装包」，给出下载页链接 | 让用户自己去猜；或说「可能环境有问题」就结束 |
| `dotnet --version` 完全找不到命令 | 提示可能未装、未重启终端、PATH 未生效三种原因，并给对应处置步骤 | 静默跳过，继续往下建目录 |
| 系统不是 64 位或低于 Windows 10 | 立即停止项目，说明「本软件不支持该系统」，不继续安装 | 硬着头皮装下去，留下后期无法打包的坑 |
| 安装过程提示需要管理员权限 | 提示两条路：找 IT 要权限，或改为便携安装（解压到用户目录）；不许让用户去破解权限 | 教用户关闭 UAC 或修改系统安全设置 |
| 杀毒软件删除安装程序 | 提示临时关闭杀软 → 装完立即恢复 → 把安装包加入白名单 | 让用户永久关闭杀软 |
| 安装时勾了过多组件（30 分钟未完成 / 磁盘爆满） | 中断安装，改勾「.NET 桌面开发」后重装 | 让用户一直等，或建议清理系统盘以外的方式硬塞 |

### 关键实现要点

**原文「AI 要做的事」7 条，一条不落（编号沿用原文）：**

1. 在 `翻译软件\src\` 下创建项目 `TranslatorApp`（`net10.0-windows` + `UseWPF`，`OutputType=WinExe` 保证不弹黑窗）。

3. 实现托盘图标 + 右键菜单（显示主窗口 / 退出）。
4. 实现主窗口（一个空窗口，标题显示版本号 `翻译软件 v0.1`）。
5. 实现单实例运行（防止重复双击打开多个）。
6. 写一个 `README-开发.md` 放在 `src\` 下，说明每个文件夹干嘛的。
7. 编译出 exe，放到 `翻译软件\release\v0.1\`。

**技术要点（这些是最容易做错的地方）：**

8. **托盘用 `System.Windows.Forms.NotifyIcon`**（在 csproj 里加 `UseWindowsForms=true`，或用 WPF 原生托盘库），不要为了托盘引入第三方包——WPF 与 WinForms 互操作是官方支持的。
9. **图标路径不能用当前工作目录**：用 `Environment.ProcessPath` 定位 exe 所在目录，再 `Path.Combine` 到 `assets\`；`Path.Combine` 全程不许用字符串拼接（中文/空格路径会炸）。
10. **单实例用全局命名 `Mutex`**（`Global\` 前缀，名字固定如 `Global\TranslatorApp.SingleInstance`），第二次启动时把已有窗口 `Show()` 到前台并**立即退出自己**，不许弹「已经运行了」的错误框。
11. **Mutex 要用 `try/catch (AbandonedMutexException)`**：上一次进程异常退出会留下被遗弃的互斥体，必须能正常接手。
12. **WPF 默认关窗不退出**，必须显式决定退出策略：主窗口关闭时若按决策 1-2 要常驻托盘，则 `ShutdownMode=OnExplicitShutdown` 并在托盘「退出」里调 `Application.Current.Shutdown()`。
13. **退出前必须 `NotifyIcon.Dispose()`**（最好再 `Visible=false`），否则托盘会残留一个点不动的幽灵图标。
14. **全局异常兜底**：`Application.DispatcherUnhandledException` + `AppDomain.CurrentDomain.UnhandledException` + `TaskScheduler.UnobservedTaskException` 三个都要接，写日志 + 中文提示，不许直接崩出 WPF 的英文崩溃框。
15. **主窗口只是空壳**，本阶段不许往里放任何翻译、取词、历史控件；窗口标题与「关于」里显示的版本号必须从程序集版本读，不许手写两份。
16. **exe 必须能脱离项目文件夹运行**：把 exe 复制到桌面双击仍能启动（这是 T1 验收项，也是阶段 9 打包的前置验证）。

### 必须实现的异常处理

| 异常场景 | 期望行为 | 不允许的表现 |
|---|---|---|
| 重复双击 exe | 只允许一个进程；第二次启动把已有窗口显示到前台后自身退出 | 弹出第二个窗口 / 弹「程序已在运行」错误框 / 出现两个托盘图标 |
| 上一次进程异常退出留下被遗弃的 Mutex | 捕获 `AbandonedMutexException`，正常接手并继续启动 | 直接崩溃或永久无法启动 |

| 关闭主窗口后进程仍在任务管理器 | 按决策 1-2 明确行为：常驻托盘则提示「已最小化到托盘」；不常驻则彻底退出 | 用户以为关了，进程却一直偷偷跑 |
| 退出后托盘图标残留 | 退出前 `NotifyIcon.Dispose()`；残留时说明是 Explorer 未刷新，不是进程没退 | 留下一堆点不动的幽灵图标 |
| 启动时发生未处理异常 | 捕获三个兜底事件，写 `翻译软件\tools\日志\报错.log`，弹中文提示「启动失败，日志已保存到……」 | 弹出英文崩溃框 / 静默退出什么都看不到 |
| 程序放在只读目录（如 `C:\Program Files\`） | 本阶段不写任何配置文件；日志写失败时降级到 `%TEMP%` 且不崩溃 | 因写日志失败导致启动失败 |

| 杀软把刚编译的 exe 删掉 | 提示这是阶段 9 决策 9-4 的已知问题，先加白名单 | 反复重新编译硬碰，或建议用户卸载杀软 |

### 关键实现要点

**原文「AI 要做的事」8 条，一条不落（编号沿用原文）：**

1. 在 `src\` 下新建独立模块（`src\Core\Input\`），钩子的所有代码只在这里，不许写进 `App.xaml.cs` 或窗口类。
2. 实现低级鼠标钩子：捕获左键按下 / 移动 / 抬起。
3. 实现低级键盘钩子（或实时查键状态）：判断 `Ctrl` 和 `Alt` 是否按住。
4. 实现状态机：`空闲 → 按下(Ctrl+Alt+左键) → 拖拽中 → 抬起`，处理各种异常情况（中途松开 Ctrl、按 Esc 取消、鼠标移出屏幕）。
5. 实现全屏透明遮罩窗口（覆盖所有显示器）。
6. 在遮罩上绘制选框。
7. 松手后，把选框坐标输出到调试日志 `翻译软件\tools\日志\框选坐标.log`。
8. 暂时不做取词，只弹个提示框显示坐标，方便测试。

**原文「关键异常处理清单」，逐条落到实现（编号沿用原文）：**

9. 拖拽过程中松开 `Ctrl` 或 `Alt` → 立即取消框选。
10. 拖拽过程中按 `Esc` → 取消框选。
11. 框太小（小于 `10×10` 像素）→ 视为误触，忽略。
12. 多显示器 → 坐标要正确（注意每个显示器的缩放比例）。
13. 屏幕缩放 125% / 150% → 坐标要换算回真实像素。

**技术要点（原文常见坑 + 补充）：**

14. **钩子回调里绝不允许做耗时操作**（不写文件、不发网络、不 `Thread.Sleep`、不 `lock` 争用），必须**立刻返回**；需要干的活一律 `PostMessage` 给主线程（钩子必须在有消息循环的线程上安装，业务在主线程做）。
15. **回调委托必须用字段长期持有**，否则 GC 回收后钩子失效（这是「用一会儿就失灵」的头号原因）。
16. **`SetWindowsHookEx` 返回 `IntPtr.Zero` 必须判空并报错**，不许继续跑；`UnhookWindowsHookEx` 在进程退出前必须调用。
17. **钩子被系统摘除的检测与自愈**：记录 `LowLevelHooksTimeout` 超时现象，提供「每 30 秒心跳自检 + 必要时重装钩子」，并在日志里记录重装次数。
18. **遮罩窗口绝不能吃掉鼠标事件**：必须加 `WS_EX_TRANSPARENT`（穿透）+ `WS_EX_LAYERED`（透明）+ `WS_EX_TOOLWINDOW`（不进 Alt-Tab）+ `WS_EX_NOACTIVATE`（不抢焦点），用 `Show()` 而不是 `Activate()`。
19. **遮罩必须覆盖整个虚拟屏**（多显示器时是一块大矩形，含负坐标），不是主显示器。
20. **不按 `Ctrl+Alt` 时绝不许影响正常鼠标操作**：钩子回调必须 `return CallNextHookEx(...)`，不许无条件 `return 1` 吞掉事件；正常点击、拖文件、拖滚动条都必须照旧。
21. **高 DPI 坐标三套要分清**：Win32 物理像素（钩子拿到的）、WPF DIP（XAML 用的）、屏幕坐标（`GetCursorPos` 给的）——互相转换只走 `DpiHelper`，不许在业务代码里手算比例。
22. **`app.manifest` 必须声明 `PerMonitorV2`**，否则混合缩放的多显示器下选框会错位。
23. **快速甩鼠标会漏 `WM_MOUSEMOVE`**：以「最后一次已知位置」为拖拽中点，抬起时以抬起点为准，不要假设事件连续。
24. **双击 Ctrl 模式**（决策 2-2 选 C 时）：要区分「双击」与「按着 Ctrl 拖拽」，双击阈值建议 400 毫秒且两次之间无其他键按下，防误触。
25. **状态机必须有超时兜底**：拖拽状态超过 60 秒没有任何事件 → 强制回到空闲，防止状态卡死导致软件「再也不响应框选」。

### 必须实现的异常处理

| 异常场景 | 期望行为 | 不允许的表现 |
|---|---|---|
| 拖拽到一半松开 `Ctrl` 或 `Alt` | 选框立即取消，不留痕、不出任何结果 | 继续画框；或松手后照样触发取词 |
| 拖拽中按 `Esc` | 选框取消，状态机回空闲 | 无反应；或 Esc 被吞掉导致别的软件收不到 |
| 只点一下不拖（框不到 10 像素） | 什么都不发生，状态机回空闲，正常点击穿透给下面的软件 | 弹出 0×0 的提示框；或吃掉这次点击 |
| 不按 `Ctrl+Alt` 直接拖左键 | **不能**出现选框，事件原样传给系统 | 干扰正常拖拽文件、拖滚动条、拖选文字 |
| 鼠标拖出虚拟屏边界 | 坐标钳制到虚拟屏范围，选框不越界、不崩 | 出现负数宽高、坐标溢出、窗口跑到屏幕外 |
| 多显示器（含不同缩放） | 每个显示器独立换算，选框与鼠标严格对齐 | 第二块屏上选框偏移；或者只覆盖主显示器 |
| 屏幕缩放 125% / 150% / 200% | 选框位置与尺寸正确，坐标可换算回真实像素 | 选框比鼠标慢半拍或整体偏移 |
| 框选过程中钩子被系统摘除 | 心跳自检发现后自动重装并记日志；期间那次框选安静失败 | 软件从此永久失灵，用户毫无察觉 |
| 鼠标移到以管理员运行的程序上框选 | 提示「该程序权限更高，请以管理员身份重启本软件」（阶段 8 提供按钮） | 静默无反应，让用户以为软件坏了 |
| 全屏独占游戏内框选 | 记录为**已知限制**（独占全屏抓不到），建议改无边框窗口模式 | 反复尝试绕过，或谎称已支持 |
| `Ctrl+Alt+Del` / UAC 安全桌面 / 锁屏期间 | 钩子收不到事件属正常；恢复后自动重装钩子并继续可用 | 锁屏后钩子失效且不恢复 |
| 遮罩窗口创建失败（显存/资源不足） | 放弃本次框选，写日志，不崩溃，不影响下次 | 抛异常导致主程序退出 |
| 遮罩创建后进程崩溃 | 下次启动时确保没有残留的全屏黑窗（进程退出即销毁窗口） | 屏幕上留下一层点不动的灰色遮罩 |

## 阶段 3 · 取词（把框里的内容变成文字）

### 技术目标

框选之后，能拿到框里的**文字内容**（一个字符串），并按「剪贴板优先 / OCR 兜底」的双通道策略完成取词，最后做语言自动判断（中文占比 > 30% 判为中文，译文要翻成英文，否则翻成中文）。**本阶段还是不翻译**，只把识别到的文字显示在临时提示框里。验收以「网页文字准确率 100%、扫描件 ≥95%、字幕 ≥90%、小字 ≥85%、剪贴板内容不被破坏」为准。

### 前置依赖

- 前置阶段：**阶段 2 验收通过**（能稳定拿到框选矩形，坐标换算正确）。
- 必须先由用户选定的决策点：**3-1（取词方式：纯 OCR / 纯剪贴板 / 混合）**、**3-2（OCR 引擎：Windows 自带 / Tesseract / 云端）**、**3-3（图像预处理：不处理 / 放大+灰度 / 二值化+分行）**。
- 接口依赖：**`ITextCapture` 在本阶段自然成形**（定义在 `src\Core\Abstractions\ITextCapture.cs`），两个实现类 `ClipboardTextCapture` / `OcrTextCapture`；阶段 10 只做「正式化 + 注释 + 文档化」，不再改结构。
- 用户侧前置：第一次使用 Windows OCR 前可能要装语言包：
  1. `Win + I` → 「时间和语言」→「语言和区域」；
  2. 点中文（简体）右边的「…」→「语言选项」；
  3. 在「可选语言功能」里把「光学字符识别」装上（若没有这一项说明系统已支持）；
  4. 英文同样操作一次。
- 必须已确认：用户日常主要翻译什么（网页 / PDF / 视频 / 游戏 / 论文），这决定 OCR 参数调优方向（阶段 0 已收集）。

### 关键实现要点

**原文「AI 要做的事」，一条不落（分组与编号沿用原文）：**

*如果选了 A 或 C（含剪贴板）：*
1. 实现「保存当前剪贴板内容 → 发送 `Ctrl+C` → 读取新剪贴板 → 还原原剪贴板」。
2. 加超时保护：200 毫秒内剪贴板没变化就算失败。
3. 处理剪贴板里有图片/文件的情况。

*如果选了 B 或 C（含 OCR）：*
4. 用 `Graphics.CopyFromScreen` 截取框选区域的画面。
5. 如果选了 3-3 的 B 或 C，做图像预处理。
6. 调用 OCR 引擎识别。
7. 处理识别结果：去掉多余空行、合并被错误断开的行、去掉首尾空格。

*通用：*
8. 做**语言自动判断**：识别出的文字里中文字符占比 > 30% 就认为是中文（译文要翻成英文），否则认为是外文（翻成中文）。
9. 加一个「调试模式」：按 `Ctrl+Alt+D` 能把框选区域的截图存到 `翻译软件\tools\素材\调试截图\`，方便排查识别问题。
10. 结果显示在临时提示框里。

**技术要点（原文常见坑 + 补充）：**

11. **判断剪贴板是否更新用 `GetClipboardSequenceNumber`**（序号比对），比「内容比对」可靠；发送 `Ctrl+C` 前可先清空，避免读到旧内容（原文坑：「剪贴板取到的是旧内容」）。
12. **剪贴板操作要重试**：`OpenClipboard` 失败（被别的软件占用）时重试 3 次、间隔 50 毫秒（原文坑）。
13. **还原剪贴板必须支持多格式**：用户剪贴板里可能是一张图、一个文件、一段富文本——备份与还原都要覆盖，不许只备份纯文本。
14. **发送 `Ctrl+C` 用 `SendInput`**，并且**先确保自己按住的 `Ctrl`/`Alt` 不会污染组合键**（框选刚结束，修饰键状态可能还没弹起，要等/清理后再发），否则目标程序收到的是 `Ctrl+Alt+C`。
15. **OCR 引擎必须初始化一次常驻复用**：每次重新 `TryCreateFromLanguage` 会慢 0.5-2 秒（原文坑：「识别速度慢」）。
16. **WinRT OCR 是异步 API**，在 WPF 里要通过 `AsTask()` 适配 `async/await`，并且注意 STA 线程与 `SoftwareBitmap` / `BitmapDecoder` 的释放。
17. **注意 `OcrEngine.MaxImageDimension`**：截图超过引擎上限要按比例缩小或分块识别，否则直接抛异常。
18. **先检测语言包再调用**：`OcrEngine.AvailableRecognizerLanguages` 为空/缺中英文时，给出图文安装引导，不要等抛「不支持的语言」异常（原文坑）。
19. **截图与坐标全用物理像素**：`CopyFromScreen` 吃的是物理像素，`DpiHelper`（阶段 2）负责 DIP 换算，多显示器负坐标要正确处理（原文坑：「多显示器截图错位」）。
20. **语言判断要健壮**：先剔空白与标点，再算中文占比；结果少于 2 个字符视为无效识别，不往下走。
21. **OCR 结果乱码的排查方向**：源语言设错、框选包含过多背景（原文坑）——都写进调试日志，便于定位。
22. **结果清理不许「合并所有行」**：中文译文要保留段落结构，行合并只在「上一行结尾无标点且下一行首字母小写」这类明显断行时做。
23. **每次识别后释放 GDI / WinRT 对象**：连续 20 次内存不许持续增长（T3-8 的判定标准）。

### 必须实现的异常处理

| 异常场景 | 期望行为 | 不允许的表现 |
|---|---|---|
| 剪贴板被别的软件占用 | 重试 3 次、间隔 50 毫秒；仍失败则跳过剪贴板通道转 OCR | 直接报「剪贴板被锁定」英文异常；或整体失败 |
| 发送 `Ctrl+C` 后剪贴板 200 毫秒内无变化 | 判定剪贴板通道失败 → 自动转 OCR；并且**先还原用户原来的剪贴板** | 继续等下去卡住；或把旧内容当识别结果 |
| 剪贴板里原本是图片 / 文件 / 富文本 | 备份与还原覆盖多格式，用户粘贴回来的东西一模一样 | 只备份文本，把用户复制的图片弄丢 |
| 剪贴板还原失败 | 记日志、不阻塞主流程，绝不为难用户 | 弹窗纠缠「还原剪贴板失败」打断翻译 |
| Windows OCR 语言包缺失 | 调用前检测，给出图文安装引导（Win+I → 语言和区域 → 语言选项 → 光学字符识别） | 抛异常崩溃；或只说「OCR 失败」 |
| 框选区域没有文字 | 返回空结果，提示「没有识别到文字」，不报错不崩溃 | 弹异常堆栈；或显示空白窗口没有任何说明 |
| 框选区域超小（如 20×20 像素） | 不崩溃，给出合理提示（「区域太小」） | 抛数组越界 / 图像尺寸异常 |
| 截图失败（区域超出屏幕、显示器被拔掉） | 先把区域钳制到虚拟屏内；仍失败则提示「无法截取该区域」 | 崩溃；或截出一张全黑图当识别结果 |
| OCR 引擎初始化失败 | 降级为「仅剪贴板」模式并明确提示用户当前能力受限 | 静默失败，让用户以为框选没反应 |
| 识别结果全是乱码 / 纯符号 | 判为无效识别，提示「没有识别到有效文字」，把原图存调试目录便于排查 | 把一堆符号送去翻译 |
| 连续识别 20 次 | 每次都正常，内存不持续增长 | 内存一路上涨，第 20 次变卡 |
| 调试截图目录不存在 / 无写权限 | 自动创建；创建失败则提示并关闭调试模式，不影响识别 | 因写截图失败导致识别失败 |
| OCR 关闭状态下框选扫描件 | （阶段 8 的配置开关生效后）提示「OCR 已关闭，无法识别此内容」 | 静默返回空，用户不知道原因 |

**原文「AI 要做的事」8 条，一条不落（编号沿用原文）：**

1. **定义统一接口**（升级通道的地基，非常关键）：`ITranslationEngine` —— 名字（"DeepSeek" / "Google免费" / …）、是否可用（Key 填了吗？网络通吗？）、翻译(文本, 源语言, 目标语言) → 译文、剩余额度（能查就查，查不到返回「未知」）。

3. **实现免费引擎**：谷歌端点、必应端点各一个实现类。
4. **实现调度器**：按优先级依次尝试，第一个成功就返回；全部失败返回友好错误。
5. **实现降级状态机**：`正常` → 用 DeepSeek；`降级中` → 用免费通道，同时后台每 30 分钟回探一次；`已恢复` → 切回 DeepSeek，托盘弹气泡提示。
6. **实现本地缓存**：同样的原文 + 同样的目标语言，短时间内不重复请求（默认缓存 24 小时）。
7. **实现错误处理**：网络不通、Key 错误、额度不足、超时，各有各的提示话术，不能只弹「出错了」。
8. **配置项**：API Key、超时时间、引擎优先级、缓存开关。

**技术要点（原文常见坑 + 补充）：**

9. **prompt 三要素**：明确「只输出译文，不要任何解释」；「严格按原文翻译，不增不减」；保留原文格式（换行、代码块、公式）。温度调低，减少「大模型爱加戏」。
10. **译文后处理**：剥离残留的 prompt 回声（如「好的，以下是翻译结果：」）、去掉包裹的引号与首尾空白。
11. **所有网络请求必须设超时（建议 10 秒）和取消机制**（原文坑：「超时没处理」会导致界面卡死）。
12. **免费接口 429 处理**：加请求间隔（例如 200 毫秒）+ 降级到下一个通道（原文坑）。
13. **免费端点失效的识别**：返回 HTML、404、字段结构变化都判为「通道不可用」，标记冷却 30 分钟，不许每次翻译都去撞墙。
14. **API Key 只能从配置读**，不许硬编码；日志与异常信息里要脱敏（绝不打印 `sk-` 内容）；提交 Git 前检查一遍（原文坑）。
15. **缓存键**用 `SHA256(原文 + 源语言 + 目标语言 + 引擎)`；缓存要有条数上限与体积上限，并支持关闭。
16. **长文分段**：超过约 2000 字符按段落切分后翻译再拼接，保证 500 字长文完整不截断。
17. **全程 `async/await`**：UI 线程只负责显示；网络、缓存、调度都不许同步阻塞。
18. **语言判断结果驱动 target**：阶段 3 的 `LanguageDetector` 输出决定「翻成中文」还是「翻成英文」；用户显式指定语言时以用户设置为准。
19. **同时只有一个在途请求**（与阶段 5 的「防连点」呼应）：调度器要能被取消，旧请求的返回结果不许覆盖新请求。
20. **降级回探必须静默**：回探失败不许弹窗、不许写错误弹窗，只记日志；回探成功才弹一次气泡。

### 必须实现的异常处理

| 异常场景 | 期望行为 | 不允许的表现 |
|---|---|---|
| 拔网线 / 关 WiFi 后翻译 | 1 秒内给出「网络连接失败，请检查网络」中文提示，界面不卡住 | 界面卡死；或抛一堆英文 socket 异常 |
| API Key 填错（401） | 提示「API Key 无效，请检查设置」，**不是**一堆英文报错 | 把服务端英文 JSON 原样弹给用户 |
| Key 欠费 / 额度耗尽 | 自动切到免费通道，翻译照样出结果，并记日志 | 直接失败；或反复重试主通道烧时间 |
| 429 限流 | 加 200 毫秒请求间隔 + 降级到下一通道 | 立即无限重试，把额度/信誉打光 |
| 请求超时（> 10 秒） | 用取消令牌中止，提示「翻译超时，请重试」并允许重试 | 一直转圈；或吞掉异常显示空白 |
| 引擎返回空内容 / 只有解释没有译文 | 视为失败 → 降级下一个引擎；全失败给「本次翻译失败，可换引擎重译」 | 把「好的，以下是翻译：」当译文显示 |

| 连续翻译 50 次 | 不崩溃、内存稳定、日志完整 | 内存持续上涨；日志缺失无法追溯 |
| 译文长度异常（比原文短 80% 以上 / 长 5 倍以上） | 记日志并标记可疑，显示时给一次重试入口 | 静默返回明显不对的结果 |

### 关键实现要点

**原文「AI 要做的事」8 条，一条不落（编号沿用原文）：**

1. 做悬浮窗界面（WPF）：上部译文（自动换行、可滚动、字号可调）；下部按钮条 —— `复制` `朗读`(可先占位) `换引擎重译` `固定`(不让它消失) `关闭`；顶部显示用的哪个引擎 + 耗时（小字灰色）。
2. 窗口属性设置：`Topmost = true`（永远在最上层）、`ShowInTaskbar = false`（不占任务栏）、`WindowStyle = None`（无边框）、`AllowsTransparency = true`（支持圆角）。
3. 实现定位逻辑（决策 5-2）。
4. 实现消失逻辑（决策 5-3，含悬停暂停）。
5. 实现复制：点一下 → 进剪贴板 → 按钮变成「已复制 ✓」→ 2 秒后恢复。
6. **串起完整流程**：框选 → 加载中动画 → 翻译 → 显示结果 → 出错显示错误。
7. **加载中要有反馈**：翻译要 0.3-2 秒，这段时间窗口必须显示「翻译中...」转圈，不能让用户以为死机了。
8. **防连点**：正在翻译时再次框选，要取消上一次请求，只显示最新结果。

**技术要点（原文常见坑 + 补充）：**

9. **定位按「工作区」而不是「屏幕」计算**（要扣掉任务栏），否则右边缘 / 下边缘框选时窗口会被任务栏挡住（原文坑）。
10. **窗口不许抢焦点**：设 `ShowActivated = false`，用 `Show()` 而不是 `Activate()`，否则原来的软件失去焦点、光标跳走（原文坑）。
11. **判定失焦时要排除「点到自己窗口」的情况**，否则窗口会「一闪就不见了」（原文坑）。
12. **绝不给悬浮窗设 `WS_EX_TRANSPARENT`**（鼠标穿透），否则按钮点不动（原文坑）；鼠标穿透只属于阶段 7 的覆盖层。
13. **长文本设最大高度**（例如屏幕高度的 60%），超出部分滚动，否则窗口会比屏幕还高（原文坑）。
14. **半透明不要全透明**：用 95% 不透明度或纯色背景，否则内容发虚看不清（原文坑，同时是决策 5-1 的取舍依据）。
15. **窗口实例只保留一个**：每次都复用同一个实例、只更新内容与位置，避免反复创建窗口导致句柄泄漏。
16. **消失计时用 `DispatcherTimer` + 悬停暂停**：鼠标进入窗口暂停计时、离开重新计时（决策 5-3 的关键细节）；「固定」按钮直接取消计时。
17. **错误也必须显示在同一个窗口里**（有内容、有关闭按钮），不许出错时什么都不弹——「全流程没有一次是『什么都没发生』」是本阶段验收项。
18. **复制后 2 秒复原要可重入**：连续点复制不许产生多个计时器或状态错乱。
19. **「换引擎重译」要跳过上一次成功的引擎**，直接试下一个；全部试完则提示无可用引擎。
20. **UI 与 Core 不许互相渗透**：窗口只通过 `IDisplayPresenter` 与管线交互，不许在窗口代码里直接发 HTTP。

### 必须实现的异常处理

### 关键实现要点

**原文「AI 要做的事」7 条，一条不落（编号沿用原文）：**

1. 设计数据库表结构：翻译记录表 —— `id`（主键）、原文、译文、源语言 / 目标语言、用的哪个引擎、耗时（毫秒）、是否收藏、创建时间。
2. 实现数据访问层（增、删、查、改、搜索）。
3. 实现历史记录窗口（列表 + 搜索框 + 操作按钮）。
4. 实现自动清理（默认保留 30 天或 5000 条，收藏的不删）。
5. 在悬浮窗上加「最近 5 条」简版列表。
6. 托盘菜单加「历史记录」入口。
7. **加隐私开关**：设置里能选择「不记录历史」（有些人翻译的是敏感内容）。

**技术要点（原文常见坑 + 补充）：**

8. **数据库锁**：每次操作用独立连接、用完立刻释放（或用连接池），避免 `database is locked`（原文坑）。
9. **开启 WAL 模式**，读写并发更稳；写入失败要重试 3 次、间隔 100 毫秒，最终失败只记日志，**绝不影响翻译与显示**。
10. **时间统一存 UTC，显示时转本地时区**（原文坑）。
11. **中文搜索**：SQLite 的 `LIKE` 对中文没问题，但要注意大小写与空格；数据量大或需要更准的匹配时用 FTS5 全文索引（原文坑）。
12. **CSV 导出必须带 UTF-8 BOM**，否则 Excel 打开乱码（原文坑）。
13. **清理任务必须真的跑起来并写日志确认**（原文坑：几个月后数据库几百 MB）——启动时跑一次 + 每天定时一次，日志记录「删除 N 条、保留收藏 M 条」。
14. **「收藏」是清理的保护区**：收藏记录既不按天数删也不按条数删。
15. **「不记录历史」开关打开后一条都不许写**：包括日志里也不许出现原文全文。
16. **列表虚拟化**：`VirtualizingStackPanel` + 分页加载，1 万条时打开 < 1 秒、搜索 < 500 毫秒。
17. **数据库位置与决策 8-2 统一**：默认 `%APPDATA%\翻译软件\history.db`；存在 `portable.txt` 时改用 exe 同目录；数据库文件不许散落在 `翻译软件\` 里（原文 T6-9）。
18. **数据库损坏自愈**：捕获 `SqliteException` → 把损坏文件重命名为 `history.db.broken-<时间戳>` → 重建空库 → 提示「历史数据库已重建」，不崩溃。
19. **查询全异步**：UI 线程不许直接查库，避免大数据量时界面假死。
20. **角落面板遵守「不抢焦点、不进任务栏、可一键隐藏」**，位置按工作区（扣任务栏）计算，与悬浮窗同一套定位工具。

### 必须实现的异常处理

| 异常场景 | 期望行为 | 不允许的表现 |
|---|---|---|
| 数据库被锁（`database is locked`） | 独立连接 + 重试 3 次间隔 100 毫秒；仍失败则本次不记录并写日志，**翻译显示不受影响** | 弹错误框打断翻译；或整个软件卡住 |
| 数据库文件损坏 | 重命名备份 + 自动重建空库 + 提示「历史数据库已重建」，能启动 | 启动崩溃；或每天重复报错 |
| 数据库文件被手动删除 | 启动时自动重建，不崩溃（T6-10） | 启动失败 |
| 磁盘写满 / 无写权限 | 历史降级为内存模式并提示，翻译照常可用 | 因写历史失败导致翻译不可用 |
| 记录无限增长 | 清理任务启动时 + 每天执行一次，日志留痕（T6-5） | 清理写了但从没执行过 |
| 收藏的记录被清理 | **绝不允许**：清理 SQL 必须带 `WHERE 是否收藏 = 0` | 收藏记录被误删 |
| 导出 CSV 用 Excel 打开乱码 | 导出文件带 UTF-8 BOM | 乱码，用户以为数据坏了 |
| 时间显示成 UTC | 存储 UTC、显示本地时间 | 时间差 8 小时 |
| 搜索中文搜不到 | 检查编码、大小写、空格处理；必要时启用 FTS5 | 搜不到就说「数据库没这条」 |
| 打开「不记录历史」后仍写入 | 开关必须同时拦截「写入」与「最近 5 条」来源 | 悄悄记录敏感内容 |
| 插入 10000 条测试数据后打开窗口 | 打开 < 1 秒、搜索 < 500 毫秒（T6-7） | 打开卡死几分钟 |
| 角落面板挡住内容 / 抢焦点 | 面板不抢焦点、可一键隐藏、位置按工作区计算 | 面板盖住用户正在看的内容且关不掉 |
| 软件重启后历史丢失 | 持久化必须生效（T6-2） | 用了内存存储却说已持久化 |

## 阶段 7 · 显示形态 C：覆盖原文（最难的一步）

### 技术目标

译文像字幕一样**直接盖在原文的位置上**，视觉上像是原文被替换成了译文。本质是「魔术贴」：截图 → 分析每行位置与背景色 → 盖一块与背景同色的色块（看起来像擦掉了原文）→ 在色块上写译文（看起来像原文变成了译文）。技术上要交付：能返回文字块坐标的 OCR、背景分析与文字颜色自适应、按行对齐 + 自适应字号的排版引擎、鼠标穿透的覆盖窗口、以及「定位失败就降级成悬浮窗」的兜底。验收以「白底与深色模式下都像原生替换 + 复杂背景自动降级不花屏 + 鼠标穿透生效 + 滚动不错位 + 最多只有一个覆盖层」为准。

### 前置依赖

- 前置阶段：**阶段 6 验收通过**。
- 必须先由用户选定的决策点：**7-1（覆盖方式：统一半透明色块 + 译文 / 取样背景色填充 + 译文 / 不遮盖只描边；原文推荐「B 为主，A 兜底，C 作为设置项」）**、**7-2（排版方式：整段居中 / 按行对齐 / 自适应字号；原文推荐 B+C 结合）**、**7-3（交互方式：穿透展示 / 可点复制 / 悬停看原文；原文推荐 A）**。
- 接口依赖：`IDisplayPresenter` 的第三个实现 `OverlayPresenter`（阶段 5 已定义接口）；`ITextCapture` 需要升级为能返回**每行/每块的 bounding box**（阶段 3 已定义的接口要有这个能力，没有就扩展接口而非新造通道）。
- 必须已确认：用户的显示器数量与缩放（阶段 0），覆盖层在多显示器与 150% 缩放下必须正确。
- 用户侧准备：在不同背景的网页上测试——白底、深色模式、带图片的页面、带渐变的按钮。

### 关键实现要点

**原文「AI 要做的事」8 条，一条不落（编号沿用原文）：**

1. **升级 OCR 模块**：改用能返回**每个文字块坐标**的模式（如果阶段 3 选了 A，这里要补上）。
2. **背景分析**：取原文区域四边的像素，算平均色和颜色方差；方差小 → 纯色背景，走「取样填充」；方差大 → 复杂背景，降级成「半透明色块」。
3. **文字颜色自适应**：算出背景色的亮度，亮背景用深色字，暗背景用浅色字。
4. **创建覆盖窗口**：位置 = 框选区域的坐标；大小 = 框选区域的大小；置顶、无边框、鼠标穿透（`WS_EX_TRANSPARENT | WS_EX_LAYERED`）。
5. **渲染译文**：按行对齐 + 自适应字号。
6. **加淡入动画**：出现时 150 毫秒淡入，比突然出现舒服。
7. **关闭方式**：再次框选时自动关掉上一个覆盖层；按 `Esc` 关掉；点屏幕其他地方（可选）；设置里能选「自动淡出时间」。
8. **兜底**：如果定位失败（比如拿不到原文行坐标），自动降级成显示悬浮窗（阶段 5 的形态），**不能让用户「什么都没看到」**。

**技术要点（原文常见坑 + 补充）：**

9. **滚动是大坑**：屏幕上的内容是会动的，覆盖层贴在屏幕坐标上，网页一滚就错位。**最省事的做法是：检测到滚动就自动关闭覆盖层**（原文明确要求），或者设一个很短的自动消失时间（如 3 秒）。
10. **取样必须避开中间区域，只取四条边**，或取出现次数最多的颜色（众数），否则会取到文字颜色导致填充发灰（原文坑）。
11. **必须先算好字号再渲染**，不能渲染完再看有没有溢出（原文坑）。
12. **最多同时存在 1 个覆盖层**（原文坑：屏幕上留一堆）。
13. **关闭要显式清空内容再隐藏**：WPF 透明窗口的经典残影问题（原文坑）。
14. **覆盖层必须真穿透**：`WS_EX_TRANSPARENT | WS_EX_LAYERED`，加完要实测「下面的按钮还能点到」；同时要保证 Esc 仍能关闭它（键盘钩子在阶段 2 已就绪）。
15. **多显示器与 150% 缩放**：覆盖层要出现在正确的显示器上，位置与大小不偏移（走 `DpiHelper`，不许手算）。
16. **超长文本（整页）不硬撑**：行数过多或字号低于下限时，直接降级成悬浮窗显示（T7-10）。
17. **颜色方差阈值要可配置**，不同网页需要微调；阈值写死在代码里会导致「某个网站特别难看」。
18. **淡入动画不许影响鼠标穿透**：动画期间窗口仍然是穿透的，不许出现「动画这 150 毫秒点不动」。
19. **关掉覆盖层的三条路径要统一**（再次框选 / Esc / 自动淡出），都走 `OverlayCoordinator.Close()`，不许各写一份。
20. **覆盖层只是「看一眼就走」**：不做滚动跟随、不做局部重绘，把复杂度挡在门外。

### 必须实现的异常处理

| 异常场景 | 期望行为 | 不允许的表现 |
|---|---|---|
| 框选后滚动网页 | 检测到滚动**立即关闭覆盖层** | 覆盖层浮在原地与原文错位（T7-5 明确禁止） |
| 渐变背景 / 图片背景 | 自动降级为半透明色块（决策 7-1 的 A 方案），译文仍清晰可读 | 花屏；或填充色与背景差异明显很突兀 |
| 拿不到原文行坐标 | 降级成悬浮窗显示（阶段 5 形态） | 什么都不显示，用户以为软件坏了 |
| 译文溢出框外 | 先算字号再渲染；带最小字号下限，低于下限改整段显示 | 文字跑到框外或盖住别的区域 |
| 超长文本（整页框选） | 不崩溃，降级成悬浮窗 | 卡死；或渲染出巨大窗口 |
| 覆盖层挡住鼠标 | `WS_EX_TRANSPARENT` 生效，下面的按钮能正常点到（T7-7） | 网页点不动，用户以为网页坏了 |
| 覆盖层残留 / 残影 | 关闭时清空内容再隐藏；同时最多 1 个（T7-8） | 屏幕上留一堆半透明块 |
| 背景全黑 / 全白导致字看不清 | 字色对比度不足时自动加深/加描边兜底 | 黑底黑字什么都看不见 |
| 覆盖层存在时按 Esc | 关闭覆盖层（与「取消框选」互不冲突） | Esc 无反应；或把两者同时触发 |
| 关闭动画未完成又触发新框选 | 立刻结束旧动画并销毁旧窗口，只保留最新的 | 两个覆盖层同时存在 |
| 150% 缩放 / 第二块显示器上框选 | 覆盖层位置与大小正确（T7-11、T7-12） | 偏移、变形、出现在错误的屏幕 |
| 背景取样区域全被文字占据 | 用众数兜底；仍无法判断则降级半透明色块 | 填充成灰色，像打了个补丁 |

### 必须实现的异常处理

| 异常场景 | 期望行为 | 不允许的表现 |
|---|---|---|
| 配置文件是非法 JSON | 用默认值启动 + 损坏文件备份为 `config.broken.json` + 提示「配置文件已损坏，已重置」 | 双击没反应；或弹英文异常框 |
| 配置缺项 / 类型不对 | 缺哪项补哪项默认值，**不整体重置** | 一项缺失就把用户所有设置清零 |
| 配置目录无写权限（如装在 `C:\Program Files\`） | 降级到 `%APPDATA%`（或 `%TEMP%`）并提示实际生效路径 | 因写配置失败导致启动崩溃 |
| 保存过程中断电 / 写入中断 | 原子写（`.tmp` + `File.Replace`），永不产生半截配置文件 | 配置文件被写坏，下次启动全部丢失 |
| 快捷键与系统或其他程序冲突 | 提示「该快捷键已被其他程序占用，请换一个」，保留旧设置 | 静默保存一个永远不生效的快捷键 |
| API Key 解密失败（换电脑 / 换用户） | 提示「请重新填写 API Key」，其余设置不受影响 | 崩溃；或把乱码当 Key 去请求 |
| 拖动滑块频繁改设置 | 防抖 500 毫秒后只写一次文件 | 每拖一格写一次盘 |
| 导入的配置来自旧版本 | 逐项校验，能用的用、不能用的回默认，并列出被重置的项 | 直接整份覆盖导致软件行为异常 |
| 关掉「启用 OCR」后在扫描件上框选 | 提示「OCR 已关闭，无法识别此内容」（T8-8） | 静默返回空，用户不知道原因 |
| 「以管理员身份重启」被 UAC 拒绝 | 提示当前仍以普通权限运行、哪些场景会受限 | 反复弹 UAC；或静默失败 |
| 设置窗口打开时配置文件被外部改动 | 以内存中的设置为准并提示「检测到外部修改，已重新加载/已忽略」 | 界面显示与实际生效值不一致 |
| 日志级别设为「安静」 | 仍保留错误级别日志，不能连报错都不写 | 出了故障一条日志都没有 |

## 阶段 11 · 本地离线翻译兜底

### 技术目标

### 关键实现要点

**原文「AI 要做的事」6 条，一条不落（编号沿用原文）：**

1. **选型调研**：确认决策 11-1 选的引擎在 C# 里能跑起来（**这一步要先做一个小实验验证可行性，不能直接开写**）。
2. 实现 `LocalTranslationEngine`，实现 `ITranslationEngine` 接口（阶段 10 的接口在这里发挥作用了）。
3. 实现模型管理：下载、校验（MD5）、解压、删除。
4. 实现调度器集成：联网时优先云 API；断网时自动用本地；设置里能强制「只用本地」（比如处理敏感内容时）。
5. **性能优化**：模型只加载一次常驻内存；小文本批量翻译；加缓存。
6. 在设置里加「离线翻译」页：下载/删除语言包、显示占用空间、测试按钮。

**技术要点（原文常见坑 + 补充）：**

7. **分词器（tokenizer）必须和模型匹配**——这是最容易出错的一环，要重点测（原文坑：中文分词错误导致翻译结果是乱码）。
8. **模型常驻内存，只在第一次翻译时加载**，不许每次翻译都重新加载（原文坑：每次卡 10 秒）。
9. **模型文件放 `%APPDATA%`，不放 `Temp`**（原文坑：和杀软冲突，下载的模型被删）。
10. **下载必须支持断点续传 + MD5 校验**，损坏就重下（原文坑：下了一半失败文件损坏）。
11. **加内存监控**：检查是否每次都在重新加载模型（原文坑：翻译几次后内存几个 GB）。
12. **进程隔离**：本地推理崩溃不许拖垮主程序；子进程退出要能自动重启，并把本次翻译回退到云引擎。
13. **CPU 占用要设上限**：限制推理线程数与进程优先级，不许把用户电脑卡死（笔记本风扇狂响是差体验）。
14. **「只用本地」模式必须真的不走云**：用日志证明没有任何外部请求，也不产生任何费用（T11-9）。
15. **默认不下载语言包**：主 exe 保持轻量，设置页给一个明显的下载按钮（决策 11-2 选 C 的要求）。
16. **语言包列表要知道「我下载了什么、占了多少空间」**（决策 11-3 选 B：用户自选语言包）。
17. **第一次翻译要显示加载进度**，不许静默卡住 10 秒。
18. **本地译文与云端译文并存时**，结果里要标明用的哪个引擎，便于用户判断质量。

### 必须实现的异常处理

| 异常场景 | 期望行为 | 不允许的表现 |
|---|---|---|
| 断网 + 未装离线包 + 框选 | 提示「网络不可用且未安装离线包」+ 给出下载引导（T11-10） | 只报「网络连接失败」；或崩溃 |
| 模型文件被删除 | 提示「离线包未安装」，不崩溃（T11-8） | 抛文件不存在异常 |
| 模型文件损坏（MD5 不符） | 判为损坏，提示重新下载；不许拿损坏文件去推理 | 输出乱码却不说原因 |
| 下载中途断网 / 断电 | 断点续传；完成后校验 MD5；不符则重下 | 留下半截文件当成功 |
| 分词错误导致乱码 | 检测分词器与模型不匹配，提示并回退到云引擎 | 把乱码结果当译文显示 |
| 内存占用暴涨（几个 GB） | 定位是否重复加载模型；加内存监控与上限告警，必要时卸载模型释放 | 一直涨到系统卡死 |
| 本地推理子进程崩溃 | 主程序不崩；重启子进程；本次翻译回退到云并提示 | 主程序一起退出 |
| 翻译时 CPU 把系统卡住 | 限制线程数 + 降低优先级；仍超标则提示用户 | 电脑完全无响应 |
| 杀软删除模型文件 | 模型放 `%APPDATA%` + 说明书给白名单步骤 | 反复下载反复被删却不告诉用户 |
| 首次翻译等待模型加载 10 秒 | 显示加载进度与「首次加载较慢」提示 | 界面无反馈，用户以为死机 |
| 连续翻译 100 句压力测试 | 不崩溃、不漏内存（T11-11） | 内存持续增长；第 50 句变慢 |
| 删除语言包 | 删干净、磁盘空间释放、列表状态同步更新（T11-7） | 删了但空间没释放；或列表显示已安装 |

### 必须实现的异常处理

| 异常场景 | 期望行为 | 不允许的表现 |
