## 3. 用户真实用法（决定语料怎么造）

用户默认「**先框整块面板；识别不出来再一段一段框文字**」。所以：

- 语料必须两种框选都覆盖：**整块面板**（主用法）+ **单行**（兜底）。
- 两个指标：
  - **`L_行`（主指标）**：单行框选的行级精确匹配率，目标 ≥95%。
  - **`L_整块`（辅指标）**：整块面板框选的行级精确匹配率。
- 整块失败后的补救（提示重框 / 自动内缩 / 缓存）是产品功能，**不占补丁额度**。

## 4. 执行顺序（严格按序，前一步没验收不许进下一步）

### S0 造行级尺子（先做，不依赖语料）

- 最小改法：`tools/脚本/比对回放.ps1` 加 `-按行` 开关 + 新真值文件 `tools/语料/行真值.json`（每张图 → 从上到下的真值行数组，并带 `mode` 字段：`整块` / `单行`）；复用已有 `Norm()` / `EditDist()`，不新建第二套归一化。
- 自检：注入「改 1 字 / 删 1 行 / 加 1 行」→ 必须分别报 1/1/1 行错；恢复后必须 0 错。**不过 = 尺子坏，停，不许改识别代码。**
- 交付：① 行级判分输出（总行数/对/错/错法归类表 + 逐行明细）② 自检记录。

### S1 扩语料到 ≥50 行（≥5 款，三档各 ≥15 行）

- 从现有 10 张图裁框：
  - 5 张整屏（新放的）：每张裁 1~2 个「整块面板」框 + 3~4 个「单行」框；
  - 5 张 Barony 局部图：直接标注 `mode`（属性面板=整块，其余=单行）。
- 裁剪矩形要记录（图名 + x/y/w/h），存 `tools/语料/实机/整块/` 与 `tools/语料/实机/单行/`，保留 SHA-256。
- 三档背景：纯色 / 渐变 / 复杂；两种极性都要有（浅字深底、深字浅底）。
- 真值：AI 打草稿 → **用户抽查点头**（不许 AI 自己确认）。
- 闸门：任一档 <15 行 或 游戏 <5 款 = 不合格，不许进 S2。
- 注意：整屏 JPG 有压缩噪点，属真实情况，**不要锐化/去噪后再入库**。

### S2 基线实测

- 跑 release 最新版：单行框 → `L_行`；整块框 → `L_整块`。
- 交付：① `L_行` ② `L_整块` ③ 错法分类表（每类几例、占错例百分比）④ 耗时三件套（平均/中位/最慢段）⑤ 分游戏/分档/分极性分项。

### S3 数据分叉

- 只用 S2 实测数字，不许估算、不许拿段级换算。
- 交付：一张分叉结论表 = 落在哪一档 + 依据哪几个数字 + 下一步动作 + 预计消耗几轮补丁。

### S4 按分叉执行

- **补丁路径**：一轮一件事 → 构建 → 全量回放 → 报「`L_行` 对 N / 错 N + 耗时」→ 记账「补丁 n/3」。
- **引擎路径**：候选 PP-OCR / RapidOCR；**先量体积与 P95，再谈准确率**；装 `assets/引擎/` 并写进 `tools/脚本/构建.ps1` 第 3.7 步版本核对（手工拷贝 = 没换过）；同一批语料 A/B，报 `L_行` + `L_整块` + 耗时 + 体积增量。
- **整块面板专项**（若 `L_整块` 低）：优先做「提示重框 / 自动内缩」（不占额度）；若要做「文字行检测」改 `src\`，算 1 轮补丁。
- 交付：每轮一份变更申请单（病根 / 改法 / 离线证据 / 风险面 / 回退 tag）。

### S5 复测 + 记账

- `tools/日志/阶段3-验收.md` 新一节 + `成绩账本.md` 一行 + `progress.md` 状态块整块替换。

## 5. 数据分叉判据

`L_行` = 单行框选的行级精确匹配率（真实游戏画面，≥50 行，三档均衡，≥5 款）。

| `L_行` | 动作 | 补丁额度 | 出口 |
|---|---|---|---|
| **≥95%** | 达标；冻结识别逻辑，只做收口（重写基线需点头、补文档、合分支需点头） | 0 轮 | 进阶段三收口 |
| **92%~95%** | 只修「占错例 ≥30% 的单一错法」，别的挂账 | ≤2 轮 | 2 轮没到 95% → 如实交付差距 |
| **85%~92%** | 错法 ≤3 类且每类 ≥5 例 → 打补丁（按错例数从多到少，一类一轮）；错法 >3 类或多数类只有 1~2 例 → 直接转第三引擎 | 3 轮 / 0 轮 | 3 轮后仍 <90% → 转引擎 |
| **<85%** | 0 轮补丁，直接转第三引擎；唯一例外：错例 ≥80% 集中在单一错法且有历史治案 → 允许 1 轮 | 0~1 轮 | 引擎上机后重测 |

**`L_整块` 分叉：**

- ≥85%：整块面板主路径可用，保持。
- 70%~85%：加「提示重框 + 自动内缩」（不占额度）。
- <70%：产品默认引导用户逐行框；整块专项挂账，不阻塞收口。

**第三引擎入选门槛（三条全过才上机）：**

1. 同批语料 `L_行` ≥ 现引擎 + 8 个百分点；
2. 单次 P95 ≤ 1.2s；缓存后 < 100ms；
3. 体积增量 ≤ 50MB，且解压后总量 ≤ 300MB。

上机后重测：<85% → 进专属识别器分叉；85%~95% → 回本表按新分数走（补丁额度**重置 3 轮**）。

**专属识别器分叉（三条同时成立才做）：**

1. 第三引擎上机后，Barony 单款 `L_行` 仍 <85%；
2. 通用引擎在其它 ≥4 款游戏上 `L_行` ≥90%；
3. 有 ≥30 行 Barony 语料。

做法：Barony 是 GPL 开源，字体资源可直接拿 → 字形模板匹配，作为「字体指纹匹配 Barony 才走专属」的旁路，**不碰主路径**。
过拟合闸门：其它游戏任一款 `L_行` 掉 >2 个百分点 → 立即下线。

## 6. 补丁计数与止损

**算 1 轮**：改 `src\` 识别/预处理/规整逻辑；调阈值/参数；改仲裁策略（比分/换票/择优）。
**不算轮**：只改量具/语料/真值/文档/日志；只改 UI 交互（提示重框、自动内缩、同区域缓存）；纯回退。
**计数写法**：`progress.md` 状态块 `补丁 n/3`，升版本号不归零；换引擎才重置。

**止损（任一触发即停）：**

1. 3 轮用完 `L_行` 仍 <90%；
2. 连续 2 轮每轮 `L_行` 提升 <1.5 个百分点；
3. 任一轮导致其它游戏/档位掉 >2 个百分点，或中位耗时涨 >15%。

## 9. 给用户的大白话操作步骤

1. **你已经把 10 张图放进 `tools\语料\实机\` 了**（6 款游戏），这一步完成。
2. **接下来 AI 会从整屏图里裁「整块面板」和「单行」两种框**。裁完会给你一张清单，你只看一眼：这些框是不是你平时会框的位置？不是就让它改。
3. **AI 会打标准答案草稿**，你抽查 10~20 行点头。你不用一字不差校对。
4. **然后跑回放**（约 5 分钟，图多了更久），AI 报两个数：`L_行` 和 `L_整块`。
5. **看数**：
   - `L_行` ≥95% = 过关；
   - 85%~95% = 还能修，最多 3 轮补丁；
   - <85% = 停补丁，换第三个引擎；
   - `L_整块` <70% = 产品会加「提示重框 / 自动内缩」，不卡收口。
6. **什么时候停**：补丁 3 轮用完、连续两轮每轮涨不到 1.5 分、或把别的游戏拉低 >2 分——任一出现就停。
7. **你后面唯一还要做的事**：补更多真实游戏截图，尤其是「复杂背景」那一档（现在这档最少）。
